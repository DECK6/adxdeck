4과목 : 에이전트에게 지식을 전달하는 방법

0. 에이전트와 지식체계

1. 에이전틱 서치 : 에이전트가 알아서 관련 정보를 찾아가는 루프

용어설명
코퍼스 : "말뭉치", 즉 텍스트 데이터의 집합을 뜻합니다. 
특수 코퍼스는 일반적인 웹 문서가 아니라 특정 분야나 조직에만 있는 전문 텍스트 모음을 말합니다. 예를 들어 사내 규정집, 법률 판례, 의료 논문, 특정 회사의 기술 문서 같은 것들입니다. LLM이 일반 학습 데이터로는 알 수 없는 내용이라, RAG처럼 외부에서 넣어줘야 하는 대표적인 지식원을 뜻합니다.
grep : 유닉스/리눅스의 고전적인 텍스트 검색 명령어입니다. 파일들 안에서 특정 단어나 패턴이 들어 있는 줄을 그대로 찾아내 보여줍니다. 예를 들어 grep "휴가" 규정.txt라고 치면 "휴가"라는 글자가 포함된 줄을 전부 출력합니다.

grep은 임베딩 기반 유사도 검색과 대비되는 개념으로 자주 등장합니다. 유사도 검색이 "의미가 비슷한 것"을 찾는다면, grep은 "글자가 정확히 일치하는 것"을 찾는 키워드 검색 방식입니다. 최근 에이전트형 검색에서는 벡터 DB 없이 grep 같은 단순 키워드 검색을 반복해 문서를 뒤지는 접근도 쓰입니다.
소형모델 : 파라미터 수가 적어 빠르고 저렴하지만 추론 능력이 상대적으로 낮은 모델을 말합니다. 

대표적인 예시는 다음과 같습니다.

Anthropic의 Claude Haiku (Opus/Sonnet보다 작은 경량 모델)
OpenAI의 GPT-4o-mini, o1-mini 같은 mini 계열
Google의 Gemini Flash, Gemini Nano

2. RAG 개념과 원리

용어설명
파라미터 : "GPT는 수천억 개의 파라미터를 가진 모델"이라고 할 때의 파라미터는 모델 내부의 학습된 수치(가중치)를 말하며, 이 숫자가 많을수록 대체로 모델의 표현력이 커집니다.

LLM은 학습 과정에서 방대한 텍스트를 읽으며 그 지식을 수십억~수천억 개의 숫자 값으로 저장하는데, 이 숫자들이 파라미터입니다. 학습이 끝나면 이 숫자들이 더 이상 바뀌지 않아서 그 이후에 생긴 새로운 정보는 모델이 알 수 없습니다.
용어설명
청킹(chunking) : 긴 문서를 작은 조각(청크)으로 잘게 나누는 작업입니다. 문서 전체를 통째로 다루기엔 너무 크기 때문에, 문단이나 일정 글자 수 단위로 쪼개서 검색과 처리가 쉬운 크기로 만드는 것입니다.
임베딩(embedding) : 텍스트를 의미를 담은 숫자 벡터(수백~수천 개의 숫자 나열)로 변환하는 것입니다. 의미가 비슷한 문장일수록 벡터 공간에서 가까운 위치에 놓이게 되어, 숫자 계산만으로 "이 질문과 이 문서가 얼마나 관련 있는지"를 비교할 수 있게 됩니다.
Google Arts & Culture Experiments - t-SNE Map Experiment
Explore art as a 3D interactive land shaped by machine learning with @GoogleArts #GoogleArtsLab
artsexperiments.withgoogle.com
top-k : 유사도 검색에서 "가장 가까운 상위 k개"를 골라낸다는 뜻입니다. k는 개수를 나타내는 숫자로, k=5라면 상위 5개를 가져오는 것입니다.

1. 사용자의 질문을 임베딩 모델로 숫자 벡터로 변환합니다.
2. 미리 벡터로 저장해 둔 문서 조각들과 비교해 유사도(가까운 정도)를 계산합니다.
3. 유사도가 높은 순으로 정렬해서 상위 k개만 뽑아 LLM에게 컨텍스트로 전달합니다.
2020년에 발표된 이 논문의 제목은 "Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks"이며, Facebook AI Research(현 Meta AI)의 Patrick Lewis 연구팀이 썼습니다. RAG(검색 증강 생성)라는 이름이 여기서 처음 나왔습니다.

1. 역할·규칙 세팅

당신은 내 개인 OKF(Open Knowledge Format) 지식 두뇌를 만드는 빌더이자 유지·관리자입니다.
OKF v0.1 사양을 따릅니다: https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md

[전역 규칙 — 모든 후속 작업에 적용]
- 결과물은 마크다운(.md)과 단일 HTML 파일로만 만든다. 파이썬·Node·빌드 도구·서버·외부 CDN 의존 금지.
  (HTML 뷰어는 외부 네트워크 없이 로컬에서 더블클릭으로 동작해야 한다.)
- 두뇌는 brain/ 폴더 하나에 담는다. 이 폴더만 zip/Git 하면 배포가 끝나야 한다.
- 예약 파일(index.md, log.md) 외 모든 .md 파일은 비어있지 않은 `type` 프론트매터를 가진다.
  title·description·tags·timestamp 는 권장.
- 지식은 페이지 통째로 복사하지 말고 "개념(concept) 단위"로 쪼갠다.
- 관련 노드는 번들 기준 절대경로로 링크한다: [제목](/concepts/foo.md)
- 큰 변경은 반영 전에 항상 계획을 먼저 보여주고 내 승인을 받는다. 반영 후 변경 파일 목록을 보고한다.
이 규칙을 이해했으면 "확인"만 답하고, 다음 지시를 기다리세요.

2. 두뇌 뼈대(스캐폴드) 만들기

brain/ 폴더에 OKF v0.1 두뇌의 뼈대를 만들어줘.
생성할 것:
1. brain/index.md
   - 프론트매터에 okf_version: "0.1" 선언 (예약 파일이라 type 불필요)
   - 본문: 두뇌 소개 한 단락 + 아래 4개 타입 섹션, 각 섹션은 해당 폴더 index.md로 링크
2. brain/log.md
   - 변경 이력 표 (날짜 | 종류(Creation/Update) | 대상 | 설명) 헤더만, 첫 줄에 이 스캐폴드 생성 기록
3. 4개 타입 폴더와 각 index.md (목차):
   - brain/concepts/index.md
   - brain/playbooks/index.md
   - brain/references/index.md
   - brain/systems/index.md
   각 index.md 는 type 프론트매터(type: index 또는 생략 가능)와 "아직 비어 있음" 안내 한 줄.
만든 파일 트리를 보여주고 끝내줘.

3. 시드 콘텐츠 (예시 노드 + 핵심 플레이북)

*플레이북 : 반복되는 작업을, 다음에 또 할 때 빠르게 하려고 단계별로 정리해 둔 문서
brain/ 두뇌에 시드(seed) 콘텐츠를 넣어줘. 사용자가 형식을 바로 이해하도록 "예시"가 목적.
생성할 것:
1. concepts/okf.md  (type: concept)
   - OKF가 무엇인지 정제된 개념 한 장. 본문에서 아래 플레이북/레퍼런스를 링크.
2. playbooks/ingest-new-knowledge.md  (type: playbook)
   - 트리거: 사용자가 "ingest this" + 자료를 줄 때
   - 절차: ①루트 index.md 읽기 ②자료 분석 후 계획부터 제안(자동 생성 금지) ③승인 후 반영
     (개념 단위로 쪼개기, 모든 .md에 type, /절대경로 링크, 외부출처는 references/에 원문링크)
     ④해당 index.md 갱신 ⑤log.md에 한 줄 ⑥요약 보고
3. playbooks/communication-voice.md  (type: playbook)
   - 글 말투 규칙 예시 한 장 (예: '우리' 대신 '저', 과한 비즈니스체 지양 — 사용자가 나중에 직접 수정).
4. references/okf-spec.md  (type: reference)
   - OKF 사양 핵심 요약 + 원문 링크(citation):
     https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md
각 파일을 만들고, 서로 /절대경로 링크로 잇고, 각 폴더 index.md와 log.md를 갱신해줘.
마지막에 노드 간 링크 관계를 간단히 요약해줘.

4. 단일 HTML 뷰어 만들기(파이썬 금지)

brain/ 두뇌를 보고 편집하는 뷰어를 okf_viewer.html 단일 파일로 만들어줘.

제약: 순수 HTML/CSS/JS 한 파일. 외부 CDN·라이브러리·빌드·서버 전부 금지(오프라인 더블클릭 동작).
파이썬 백엔드 절대 쓰지 말 것 — 파일 읽기/쓰기는 브라우저 File System Access API로만.

기능:
1. [📂 폴더 열기] — File System Access API(showDirectoryPicker)로 brain/ 폴더를 선택해 읽는다.
   - 폴더 안 모든 .md 를 재귀로 읽어 YAML 프론트매터(type/title/description/tags)와 본문 링크를 파싱.
2. 지식 그래프 — 각 .md = 노드(점), 본문의 [..](/경로.md) 링크 = 엣지(선).
   - 외부 라이브러리 없이 <canvas> 또는 SVG로 직접 그린 간단한 force-directed 배치.
   - 점 드래그 이동, 휠 확대/축소, 점 클릭 → 우측 패널에 본문 렌더.
3. [🔍 검색] 제목·설명·태그로 필터. 타입별 색상 칩으로 보기/숨기기 토글.
4. [➕ 새 노드] type/제목/설명/태그/본문 폼 → 저장 시 해당 타입 폴더에 .md 파일로 직접 write.
   - 경로 자동 생성(slug), 프론트매터 자동 작성. 저장 후 그래프 즉시 갱신.
5. 노드 열람 중 [✎ 수정]/[🗑 삭제], [↻ 새로고침], 빈 폴더면 [🌱 시드 두뇌 만들기] 버튼(최소 노드 자동 생성).
6. 미지원 브라우저(File System Access 없음: Firefox/Safari) 감지 시 "Edge/Chrome으로 열어주세요" 안내.
UI는 한국어. 다 만들면 어떻게 여는지(Edge/Chrome 더블클릭) 한 줄로 안내해줘.
