# 답변에서 다음 질문 고르기

사용자에게 아래 항목을 한꺼번에 보여주지 않는다. 현재 질문에 답하는 데 부족한 부분을 골라 자연스럽게 묻는다.

| 지금 들은 내용 | 이어서 물을 수 있는 질문 | 정리할 내용 |
|---|---|---|
| “내 경력을 소개할 때마다 설명하기 어려워요.” | “어떤 자리에서 소개하려고 하시나요? 그 자리와 연결되는 최근 활동 하나를 들려주세요.” | 사용 목적, 직업, 대표 활동 |
| “디자인과 교육을 같이 해요.” | “같은 경험이나 개념을 두 일에 함께 쓰신 적이 있나요?” | 서로 다른 활동을 잇는 개념 |
| “이 사람과 프로젝트를 했어요.” | “두 분은 각각 어떤 일을 맡았나요? 서로 검토하는 관계도 있었나요?” | 참여·담당·검토 구별 |
| “작품 세 개를 만들었어요.” | “각 작품의 이름과 다룬 생각은 무엇인가요? 한 프로젝트에서 나온 작품인가요?” | 작품·프로젝트·개념 |
| “회사에서는 디렉터였어요.” | “언제, 어떤 프로젝트에서 어떤 역할을 맡으셨나요?” | 과거 경력과 활동 범위 |
| “개발 중인 앱과 기획 중인 전시가 있어요.” | “현재 실제로 된 것과 앞으로 하려는 것은 어디까지인가요?” | 구현·구상·미확인 상태 |
| “자료가 너무 많아요.” | “이번에는 어떤 질문에 답하면 가장 도움이 될까요?” | 필요한 자료부터 읽을 범위 |
| “이 사람 이름은 가려주세요.” | “알려주신 공개 범위대로 별칭을 일관되게 쓰겠습니다.” | 이미 명확한 선호는 다시 묻지 않음 |

## 대화의 단위

보통 `짧은 질문 → 답변 → 관계 2~5줄 요약 → 다음 질문`으로 진행한다. 답변이 풍부하면 더 많은 대상을 추출해도 되지만 사용자에게 JSON 전체를 매번 보여주지 않는다. “이건 해석이므로 가설로 두었습니다”처럼 불확실성만 분명히 알린다.

첫 모델이 생기면 “이번 프로젝트에 참고할 이전 경험은?”, “내 작품과 교육에서 공통으로 쓰는 개념은?”, “이 작업의 참여자와 담당자는?” 같은 실제 질문 하나에 답한다. 관계 수를 늘리는 것을 성공 기준으로 삼지 않는다.

## 스터디장 시연과 스터디멤버 실습

- 스터디장은 실제 자기 자료에서 짧은 인터뷰를 시연하고, 정정 한 번으로 관계와 답변이 바뀌는 장면을 보여준다.
- 스터디멤버는 자기 대화·메모·경력 자료로 시작한다. 자료가 없어도 직접 말한 경험으로 만들 수 있다.
- 처음 10~20분에 작은 모델과 첫 활용을 경험한다. 시간이 남으면 작품·프로젝트·과거 경력으로 확장한다.
- 다음 만남에서는 저장한 상태를 읽고 바뀐 일·새로운 관계부터 갱신한다.
