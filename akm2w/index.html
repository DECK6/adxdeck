# 작은 지역 창작 워크숍 참가 안내 지식 v1

## 이 지식이 답할 질문

승인된 프로그램·장소 자료로 참가 안내문을 만들 때 무엇을 확정해 쓰고, 무엇을 보류해야 하는가?

## 직접 읽은 Source

- `demo/sources/program-brief.md`
- `demo/sources/venue-guide.md`

## 확인한 사실

- 프로그램은 2026-08-22 14:00–17:00에 열린다.
- 대상은 오디오 제작 경험이 없는 성인이다.
- 기본 정원은 18명이며 참가비는 무료다.
- 사전 신청이 필요하다.
- 실습 장비는 운영팀이 제공하고 참가자는 개인 물병만 준비한다.
- 장소는 가상 생활문화센터 2층 창작실이며 13:40부터 입실한다.
- 음식물은 금지되고 뚜껑이 있는 물병은 허용된다.

## 재사용할 판단

1. 참가자에게 공개하는 사실은 승인본에서 직접 확인한 항목으로 제한한다.
2. 프로그램 개요는 대상·일정·정원·비용·준비물의 authority를 가진다.
3. 장소 안내는 입실·접수·건물 이용 규칙의 authority를 가진다.
4. 주차, 엘리베이터, 별도 휠체어 출입 동선은 확인 전까지 HOLD한다.
5. 최신 승인 변경 공지가 들어오면 변경된 항목만 새 공지로 교체하고 나머지 유효한 판단은 재사용한다.

## scope와 Context

- scope: 2026-08-22 가상 워크숍의 공개 참가 안내
- 독자: 신청을 검토하거나 참가를 준비하는 초보 성인
- 제약: 확인되지 않은 편의·접근 정보를 가능한 것처럼 쓰지 않는다.

## authority와 freshness

- 프로그램 정보: 2026-08-01 운영 승인본
- 장소 정보: 2026-08-03 장소 운영 승인본
- 더 최신인 승인 변경 공지가 같은 항목을 바꾸면 그 항목에는 최신 공지를 우선 적용한다.

## HOLD

- 주차 가능 여부
- 엘리베이터 운영 여부
- 별도 휠체어 출입 동선

## pointer

- 프로그램 기준: `demo/sources/program-brief.md`
- 장소 기준: `demo/sources/venue-guide.md`

| 확인 전까지 주차를 HOLD한다. | Knowledge v1 `HOLD` | 참가 안내문 v2 `주차 가능 여부는 아직 확인되지 않았습니다.` | reused + held |
| 나머지 승인 정보는 유지한다. | Knowledge v1 `확인한 사실` | 일정, 대상, 참가비, 신청, 준비물, 입실 시각 | reused |

## 측정 경계

- 파일 근거로 확인한 것: 기존 판단의 재사용, 변경 항목, 추가 항목, HOLD 유지
- 측정하지 않은 것: 작성 시간 절감, 정확도 향상, 업무 생산성 향상

## 복리 근거 한 문장

첫 작업에서 남긴 `확인된 사실만 공개하고 주차는 HOLD한다`는 판단을 두 번째 작업이 먼저 읽었고, 최신 변경 공지 때문에 `정원과 출입 조건`만 수정했습니다. 주차 HOLD는 그대로 보존했으므로 첫 작업의 지식이 두 번째 작업의 판단에 실제로 쓰였습니다.
02 / FLOW

완성본이 어떻게 만들어졌는지

핵심은 Source를 매번 처음부터 요약하는 일이 아니라, 첫 작업의 판단을 두 번째 작업이 먼저 읽고 적용하는 것입니다.

Source A/B 직접 읽기
→ 참가 안내문 v1 작성
→ 다음 작업에서 다시 쓸 판단을 Knowledge v1로 저장
→ Knowledge v1 선조회
→ Source C와 새 Context만 결합
→ 참가 안내문 v2와 delta 작성
→ 같은 질문·scope인지 확인
→ 기존 Knowledge를 v2로 갱신
→ 재사용된 판단을 파일 위치로 연결

첫 작업의 확인된 사실만 공개, 최신 승인 공지는 변경 항목에 우선, 주차 HOLD 판단이 두 번째 작업의 결과에 실제로 적용되었습니다.

Source

판단의 출발점이 되는 원문, 공식 문서, 회의 기록, 데이터입니다.

↑ 완성본으로

Knowledge

Source에서 확인한 사실과 여러 작업에서 다시 쓸 판단을 근거·scope·불확실성과 함께 정리한 지식입니다.

↑ 첫 등장으로

Context

독자, 사용자, 프로젝트, 시점, 제약처럼 판단의 적용 조건을 정하는 정보입니다.

↑ 5개 값으로

direct read

검색 결과나 AI 요약이 아니라 원문 파일을 직접 열어 확인하는 일입니다.

↑ 생성 흐름으로

scope

판단이 유효한 대상, 기간, 프로젝트, 조건의 범위입니다.

↑ 성공 판정으로

authority

여러 자료 중 어느 자료가 해당 결정을 확정할 권한을 가지는지 나타냅니다.

↑ 막힐 때 선택으로

freshness

자료가 현재 상황을 얼마나 반영하는지 보여 주는 최신성입니다.

↑ 막힐 때 선택으로

HOLD

근거, 권한, 접근, 최신성이 부족해 결론을 확정하지 않는 판정입니다.

↑ 성공 판정으로

Verify

저장 보고가 아니라 실제 readback과 Source 연결로 결과를 다시 확인하는 단계입니다.

↑ 프롬프트로

delta

두 버전 사이에서 재사용·수정·추가·보류된 차이입니다.

↑ 완성본으로
