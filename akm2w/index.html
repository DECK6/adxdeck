00 / WHY

채팅에 묻힌 좋은 판단

첫 작업에서 좋은 자료를 찾고, 충돌하는 정보를 구분하고, 언제 결론을 보류할지 판단해도 근거를 남기지 않으면 다음 작업에서 같은 조사와 판단을 반복합니다.

판단을 남기지 않으면

  • 같은 자료를 다시 찾습니다.
  • 이전에 확인한 조건을 다시 설명합니다.
  • 무엇을 믿고 보류했는지 다시 판단합니다.
  • 오래된 답변을 새 상황에 그대로 적용할 위험이 생깁니다.

재사용할 판단을 남기면

두 번째 작업은 처음부터 조사하지 않습니다. 기존 지식을 먼저 읽고, 새 조건과 부족한 부분만 확인합니다.

02 / PREPARE

시작 전 준비

내 에이전트에서 실행하기 전에 질문·자료·새 조건·안전한 경로를 준비합니다. 이 페이지는 읽기와 복사만 하며 어떤 입력도 저장하거나 전송하지 않습니다.

준비 체크

  • 반복해서 하는 업무 또는 프로젝트 질문 한 개를 골랐습니다.
  • 첫 번째 작업에 사용할 자료를 준비했습니다.
  • 두 번째 작업에서 새로 결합할 조건이나 자료 한 개를 준비했습니다.
  • 원본 대신 실습에 쓸 privacy-safe 복사본을 만들었습니다.
  • 내 에이전트가 읽을 수 있는 경로와 결과를 저장할 경로를 정했습니다.

넣지 않을 것

  • 개인정보와 실제 참여자 식별 정보
  • 계약서, 비공개 인사 자료, 의료·법률 분쟁 자료
  • 비밀번호, API key, token, cookie, 인증 정보
  • 공개 권한을 확인하지 못한 고객·회사 자료

하나라도 확실하지 않으면 익명화한 복사본이나 공개 샘플로 바꿉니다.

04 / LAB

CAPTURE → REUSE → PROVE

각 프롬프트는 코드 블록만 독립적으로 복사됩니다. 대괄호 안의 값만 내 상황에 맞게 바꾼 뒤, 내 AI 에이전트에서 실행하세요.

ONE FICTIONAL EXAMPLE

작은 지역 워크숍 참가 안내문

실제 조직이나 행사를 가리키지 않는 완전한 가상 사례입니다.

  • 반복 업무: 작은 지역 워크숍 참가 안내문 작성
  • 첫 자료: 승인된 프로그램 개요와 장소 안내
  • 첫 판단: 초보 성인 대상, 준비물 제공, 주차 여부는 미확인이라 단정 금지
  • 새 조건: 장소 수용 인원이 줄고, 계단만 있는 출입구 정보가 추가됨
  • 두 번째 결과: 기존 대상과 준비물 정보는 재사용하고, 정원과 접근성 안내만 수정
  • delta: 정원 변경, 접근성 조건 추가, 주차 HOLD 유지

복리의 근거는 안내문이 길어진 것이 아닙니다. “확인된 정보만 쓰기”와 “주차는 HOLD”가 유지되고, 새 자료 때문에 정원과 접근성만 바뀐 점입니다.

01 / CAPTURE / PROMPT A

첫 작업과 Knowledge v1 만들기

첫 작업 결과와 다음 작업이 다시 쓸 판단을 분리해 남깁니다.

복사 대기
당신은 첫 번째 작업을 수행하고, 다음 작업에서 다시 쓸 판단을 Knowledge v1로 남기는 AI 에이전트입니다.

[내가 제공할 값]
AKM_ROOT: [내 AKM 또는 지식 폴더의 루트 경로]
TASK_QUESTION: [이번에 해결할 반복 업무 또는 프로젝트 질문]
SOURCE_PATHS:
- [첫 번째 입력 자료 경로 1]
- [첫 번째 입력 자료 경로 2]
FIRST_OUTPUT_PATH: [첫 번째 작업 결과를 저장할 경로]
KNOWLEDGE_V1_PATH: [Knowledge v1을 저장할 경로]
CONTEXT: [이 작업의 사용자·프로젝트·시점 조건]

[안전 규칙]
- 개인정보, 계약상 비공개 정보, 비밀번호, API key, token, cookie를 읽거나 결과에 노출하지 마세요.
- 민감할 가능성이 있으면 작업을 중단하고 어떤 입력을 privacy-safe 복사본으로 바꿔야 하는지 HOLD로 적으세요.
- 제공된 경로 밖의 개인 폴더를 임의로 탐색하지 마세요.

[근거 규칙]
1. SOURCE_PATHS의 파일을 직접 읽으세요.
2. 실제로 읽은 경로를 목록으로 밝히고, 읽지 못한 경로는 성공한 것처럼 쓰지 마세요.
3. 검색 결과나 이전 AI 요약을 원문 대신 쓰지 마세요.
4. 확인할 수 없는 주장, 서로 충돌하는 내용, 권한이 불분명한 결정은 HOLD로 남기세요.
5. 사실, 해석, 재사용 판단을 구분하세요.

[작업]
1. TASK_QUESTION에 대한 첫 번째 작업 결과를 완성하세요.
2. 다음 작업에서도 다시 쓸 가치가 있는 판단만 추출하세요.
3. Knowledge v1을 아래 구조로 작성하세요.
   - 이 지식이 답할 질문
   - 직접 읽은 Source와 경로
   - Source에서 확인한 사실
   - 재사용할 판단
   - scope와 Context
   - authority와 freshness 메모
   - 충돌·불확실성·HOLD
   - 다음 작업에서 먼저 읽을 이유
   - 관련 원문으로 돌아가는 pointer/link
4. 파일 쓰기가 가능하면 FIRST_OUTPUT_PATH와 KNOWLEDGE_V1_PATH에 각각 저장하세요. 파일 쓰기가 불가능하면 저장 가능한 완전한 Markdown 두 개를 출력하세요.
5. 저장했다면 두 파일을 다시 읽고 제목, 핵심 판단, Source 경로가 실제로 들어갔는지 Verify하세요.

[최종 보고]
- 첫 번째 작업 결과 경로 또는 완전한 본문
- Knowledge v1 경로 또는 완전한 본문
- 직접 읽은 Source 경로
- 재사용할 판단 1~3개
- HOLD 항목
- Verify 결과: PASS / PASS_WITH_NOTE / HOLD / FAIL

내가 바꿀 곳

  • AKM_ROOT, TASK_QUESTION, SOURCE_PATHS
  • FIRST_OUTPUT_PATH, KNOWLEDGE_V1_PATH
  • 사용자·프로젝트·시점에 해당하는 CONTEXT

실행 후 확인할 것

  • Source를 직접 읽은 경로가 적혀 있습니다.
  • 첫 작업 결과와 Knowledge v1이 분리되어 있습니다.
  • 재사용 판단에 scope와 HOLD가 붙어 있습니다.
  • 저장했다면 실제 파일을 다시 읽은 Verify가 있습니다.
02 / REUSE / PROMPT B

Knowledge v1을 먼저 읽고 두 번째 작업 하기

첫 조사를 반복하지 않고 새 조건 때문에 부족해진 부분만 조사합니다.

복사 대기
당신은 기존 Knowledge v1을 먼저 읽고, 새 조건만 결합해 두 번째 작업을 수행하는 AI 에이전트입니다.

[내가 제공할 값]
AKM_ROOT: [내 AKM 또는 지식 폴더의 루트 경로]
TASK_QUESTION: [첫 작업과 이어지는 두 번째 질문]
KNOWLEDGE_V1_PATH: [기존 Knowledge v1 경로]
FIRST_OUTPUT_PATH: [첫 번째 작업 결과 경로]
NEW_SOURCE_PATHS:
- [새 조건 또는 새 자료 경로 1]
NEW_CONTEXT: [두 번째 작업에서 달라진 사용자·프로젝트·시점 조건]
SECOND_OUTPUT_PATH: [두 번째 작업 결과 저장 경로]
DELTA_PATH: [Knowledge v1과 비교한 delta 기록 경로]

[안전 규칙]
- 개인정보, 계약상 비공개 정보, 비밀번호, API key, token, cookie를 읽거나 결과에 노출하지 마세요.
- 민감하거나 권한이 불분명한 입력은 임의로 사용하지 말고 HOLD로 남기세요.
- 제공된 경로 밖의 개인 폴더를 임의로 탐색하지 마세요.

[선조회 규칙]
1. 다른 조사를 시작하기 전에 KNOWLEDGE_V1_PATH를 직접 읽으세요.
2. Knowledge v1에서 재사용 가능한 판단, scope, HOLD를 먼저 목록으로 만드세요.
3. NEW_SOURCE_PATHS를 직접 읽고 실제 경로를 밝히세요.
4. 기존 Source를 다시 조사해야 한다면 Knowledge v1에 근거가 부족하거나 freshness 확인이 필요한 이유를 먼저 설명하세요.
5. 읽지 못한 파일과 확인할 수 없는 내용은 HOLD로 남기세요.

[작업]
1. Knowledge v1에서 그대로 재사용할 판단을 표시하세요.
2. NEW_CONTEXT와 NEW_SOURCE_PATHS 때문에 수정할 판단을 표시하세요.
3. 새로 추가할 판단과 계속 HOLD할 항목을 구분하세요.
4. 위 구분을 근거로 두 번째 작업 결과를 완성하세요.
5. delta 기록을 아래 구조로 작성하세요.
   - reused: 그대로 재사용한 판단과 근거
   - modified: 새 조건 때문에 바꾼 판단과 근거
   - added: 새로 추가한 판단과 근거
   - held: 아직 확정하지 않은 내용과 필요한 확인
   - Knowledge v2 반영 제안
6. 파일 쓰기가 가능하면 SECOND_OUTPUT_PATH와 DELTA_PATH에 저장하세요. 파일 쓰기가 불가능하면 저장 가능한 완전한 Markdown 두 개를 출력하세요.
7. 저장했다면 두 파일을 다시 읽고 Knowledge v1의 판단이 실제 결과에 반영되었는지 Verify하세요.

[최종 보고]
- 먼저 읽은 Knowledge v1 경로
- 직접 읽은 새 Source 경로
- 두 번째 작업 결과 경로 또는 완전한 본문
- delta 경로 또는 완전한 본문
- reused / modified / added / held 요약
- Verify 결과: PASS / PASS_WITH_NOTE / HOLD / FAIL

내가 바꿀 곳

  • TASK_QUESTION, KNOWLEDGE_V1_PATH, FIRST_OUTPUT_PATH
  • NEW_SOURCE_PATHS, NEW_CONTEXT
  • SECOND_OUTPUT_PATH, DELTA_PATH

실행 후 확인할 것

  • 새 조사 전에 Knowledge v1을 직접 읽었습니다.
  • 재사용한 판단과 새로 바꾼 판단이 구분되어 있습니다.
  • 두 번째 결과에 Knowledge v1의 구체적인 판단이 보입니다.
  • delta가 reused / modified / added / held로 나뉘어 있습니다.
03 / PROVE / PROMPT C

인상평 대신 판단이 다시 쓰인 위치와 새 조건 때문에 달라진 부분을 파일 근거로 확인합니다.

복사 대기
당신은 첫 번째 작업과 두 번째 작업을 비교해 지식 복리의 근거를 확인하고, Knowledge v2 갱신 방식을 결정하는 AI 에이전트입니다.

[내가 제공할 값]
FIRST_OUTPUT_PATH: [첫 번째 작업 결과 경로]
SECOND_OUTPUT_PATH: [두 번째 작업 결과 경로]
KNOWLEDGE_V1_PATH: [Knowledge v1 경로]
DELTA_PATH: [delta 기록 경로]
KNOWLEDGE_V2_PATH: [갱신한 Knowledge v2를 저장할 경로]
RELATED_NOTE_PATHS:
- [연결 여부를 확인할 관련 노트 경로]

[안전 및 근거 규칙]
- 제공된 파일을 직접 읽고 실제로 읽은 경로를 밝히세요.
- 파일에 없는 효과, 시간 절감, 정확도 향상을 추정하지 마세요.
- 성능 향상을 주장하려면 비교 가능한 기록이 있어야 합니다. 기록이 없으면 “측정하지 않음”이라고 쓰세요.
- 충돌하거나 확인할 수 없는 내용은 HOLD로 남기세요.
- 개인정보, 계약상 비공개 정보, 비밀번호, API key, token, cookie를 결과에 포함하지 마세요.

[비교 작업]
1. 네 파일을 직접 읽고 첫 결과와 두 번째 결과의 차이를 찾으세요.
2. 두 번째 결과에서 Knowledge v1의 어떤 판단이 실제로 재사용되었는지 인용 가능한 구절이나 항목으로 연결하세요.
3. 새 Source와 Context 때문에 수정·추가된 내용을 delta와 대조하세요.
4. 다음 중 하나를 결정하고 이유를 쓰세요.
   - 새 Knowledge 노트 작성: 주제나 scope가 달라 기존 노트에 합치면 혼동되는 경우
   - 기존 Knowledge를 v2로 갱신: 같은 질문과 scope에서 판단이 발전한 경우
   - pointer/link만 추가: 기존 판단은 그대로이고 새 자료로 돌아갈 연결만 필요한 경우
5. Knowledge v2를 만든다면 기존의 유효한 판단, 새 delta, 남아 있는 HOLD를 함께 보존하세요.
6. 저장했다면 KNOWLEDGE_V2_PATH를 다시 읽고 Source, scope, authority, freshness, HOLD, pointer/link가 남아 있는지 Verify하세요.

[복리 근거 표]
- 재사용한 판단
- 첫 번째 근거 위치
- 두 번째 결과에서 쓰인 위치
- 새 조건으로 수정된 부분
- 새로 조사한 부분
- 측정된 효과 또는 측정하지 않음

[최종 보고]
- 직접 읽은 파일 경로
- 복리 근거 표
- 새 노트 / 기존 노트 갱신 / pointer-link 추가 중 선택
- Knowledge v2 경로 또는 갱신 제안
- 남은 HOLD
- Verify 결과: PASS / PASS_WITH_NOTE / HOLD / FAIL

  • 네 비교 파일 경로

  • 연결 후보인 RELATED_NOTE_PATHS

실행 후 확인할 것

  • 복리 효과를 파일의 판단과 결과로 연결했습니다.
  • 시간·정확도 개선을 측정하지 않았다면 과장하지 않았습니다.
  • 새 노트, 기존 노트 갱신, pointer/link 추가 중 하나를 골랐습니다.
  • Knowledge v2에 기존 판단과 delta, HOLD가 함께 남았습니다.
05 / JUDGE

복리 성공 체크

아래 질문에서 세 개 이상 “예”라면 복리의 흔적이 있습니다.

  • 두 번째 작업이 시작되기 전에 Knowledge v1을 읽었습니다.
  • 첫 작업에서 확인한 Source를 이유 없이 다시 조사하지 않았습니다.
  • 두 번째 결과에서 재사용된 판단을 정확히 가리킬 수 있습니다.
  • 새 조건 때문에 바뀐 부분과 그대로인 부분을 구분할 수 있습니다.
  • 확인하지 못한 내용은 여전히 HOLD로 남았습니다.
  • Knowledge v2 또는 delta가 다음 작업에서 읽을 수 있는 형태로 남았습니다.
첫 작업에서 남긴 [재사용 판단]을 두 번째 작업이 먼저 읽었고, [새 조건] 때문에 [바뀐 부분]만 수정했습니다. [HOLD 또는 유지된 경계]는 그대로 보존했으므로, 첫 작업의 지식이 두 번째 작업의 판단에 실제로 쓰였습니다.
FINAL JUDGMENT첫 작업에서 남긴 지식 때문에 두 번째 작업이 달라졌다.
06 / BLOCKED

막힐 때 대체 선택

실행 환경이 달라도 성공한 척하지 않고 정직한 HOLD와 다음 행동을 남깁니다.

에이전트가 로컬 파일을 읽지 못합니다

privacy-safe 복사본의 필요한 부분만 제공하고 “직접 파일을 읽었다”는 주장은 하지 않게 합니다. 결과에는 direct read: NOT TESTED 또는 HOLD라고 적습니다.

반복 업무를 고르기 어렵습니다

최근 한 달 안에 두 번 이상 비슷하게 물었던 질문을 찾습니다. 그래도 없으면 앞의 가상 워크숍 안내문 사례로 흐름만 연습합니다.

Knowledge v1이 너무 일반적입니다

“다음에도 잘하자”는 재사용 판단이 아닙니다. 어떤 Source를 믿었는지, 어느 scope에서 유효한지, 무엇을 HOLD했는지 다시 적습니다.

두 번째 결과가 첫 번째와 거의 같습니다

새 조건이 판단을 바꿀 만큼 구체적인지 확인합니다. 날짜만 바뀌어도 freshness 검토가 필요할 수 있지만 재사용 차이를 보여 주기에는 약할 수 있습니다.

Source가 서로 충돌합니다

하나를 임의로 고르지 않습니다. authority, freshness, scope를 비교하고도 결정할 수 없으면 충돌을 HOLD로 남기고 필요한 승인자나 정본을 적습니다.

07 / SHARE

제출·공유용 네 문장

아래 네 문장만 채우면 오늘 결과를 짧게 공유할 수 있습니다.

  1. 첫 번째 작업에서 [Source]를 직접 읽고 [재사용 판단]을 Knowledge v1로 남겼습니다.
  2. 두 번째 작업에서는 Knowledge v1을 먼저 읽고 [새 Source 또는 Context]만 추가했습니다.
  3. 그 결과 [재사용된 부분]은 유지하고 [수정·추가된 부분]만 delta로 기록했습니다.
  4. 복리 근거는 [두 번째 결과에서 실제로 다시 쓰인 판단]이며, [미확인 내용]은 HOLD로 남겼습니다.
08 / NEXT

다음 주 연결

이번 주에는 사람이 프롬프트로 Knowledge v1을 먼저 읽게 하고 결과를 비교해 delta를 남겼습니다. 다음 주에는 이 동작을 기억에 의존하지 않도록 읽기·쓰기 규칙과 Verify 주기, Learn Back 위치를 운영 규칙으로 정착시킵니다. 이번 주에 만든 Knowledge v1, v2, delta가 다음 주 규칙의 실제 입력이 됩니다.

09 / GLOSSARY

용어사전

본문의 첫 용어 주석에서 이 정의로 이동할 수 있고, 각 정의의 링크로 첫 등장에 돌아갈 수 있습니다.

AI 에이전트

목표를 받아 자료를 읽고, 도구를 사용하며, 작업 결과를 만드는 소프트웨어입니다. 이 문서에서는 Codex, Claude Code, Hermes, OpenClaw처럼 파일 기반 작업을 수행할 수 있는 환경을 폭넓게 가리킵니다.

↑ 첫 등장으로

AKM

Agent Knowledge Management의 약자입니다. 에이전트가 필요한 지식과 맥락, 절차, 검증 규칙을 찾아 쓰고 결과에서 배운 내용을 다시 반영하도록 구성하는 지식 운영 구조입니다.

↑ 첫 등장으로

authority

여러 자료가 충돌할 때 어느 자료가 결정을 확정할 권한과 신뢰도를 가지는지 나타냅니다. 공식 승인본과 개인 메모는 같은 authority로 취급하지 않습니다.

↑ 첫 등장으로

Context

사용자, 조직, 프로젝트, 시점, 제약처럼 판단의 적용 조건을 설명합니다. 같은 Knowledge라도 Context가 달라지면 결과의 범위와 표현이 달라질 수 있습니다.

↑ 첫 등장으로

delta

두 버전 사이에서 추가·수정·보류된 차이입니다. 전체 노트를 다시 쓰기보다 이번 작업에서 생긴 변화만 명확히 남길 때 씁니다.

↑ 첫 등장으로

direct read

검색 결과나 AI 요약에 의존하지 않고 원문 파일을 직접 열어 확인하는 것입니다. 실제로 읽지 못했다면 direct read를 했다고 쓰지 않습니다.

↑ 첫 등장으로

freshness

자료가 현재 상황을 얼마나 반영하는지 나타내는 최신성입니다. 최신 파일이라는 이유만으로 authority가 가장 높다고 단정할 수는 없습니다.

↑ 첫 등장으로

HOLD

근거, 권한, 접근, 최신성 등이 부족해 결론을 확정하지 않는 판정입니다. 실패를 숨기는 말이 아니라 다음에 무엇을 확인해야 하는지 남기는 안전 장치입니다.

↑ 첫 등장으로

Knowledge

Source를 읽고 여러 작업에서 다시 쓸 수 있도록 정리한 사실과 판단입니다. 원문 보존본과 구분하며 근거, scope, 불확실성을 함께 둡니다.

↑ 첫 등장으로

Knowledge v1 / Knowledge v2

Knowledge v1은 첫 작업 뒤 만든 첫 지식 버전입니다. Knowledge v2는 두 번째 작업의 새 Source와 Context, delta를 반영한 다음 버전입니다.

↑ 첫 등장으로

Learn Back

실행과 Verify에서 발견한 성공·실패를 지식, 맥락, 절차, 평가 규칙의 수정으로 돌려보내는 과정입니다. 다음 작업의 입력 품질을 높이는 데 목적이 있습니다.

↑ 첫 등장으로

pointer / link

원문이나 관련 노트의 위치를 가리키는 연결입니다. 같은 내용을 여러 곳에 복제하지 않고 정본으로 돌아갈 경로를 남깁니다.

↑ 첫 등장으로

scope

판단이 유효한 대상, 기간, 프로젝트, 조건의 범위입니다. scope가 다른 결론을 하나의 보편 규칙처럼 합치지 않습니다.

↑ 첫 등장으로

Source

판단의 출발점이 되는 원문, 공식 문서, 회의 기록, 데이터, 안내문입니다. 원본은 해석과 섞지 않고 보존하는 것이 기본입니다.

↑ 첫 등장으로

Verify

결과가 요구 조건과 근거를 충족하는지 다시 확인하는 단계입니다. 파일을 저장했다는 보고보다 실제 readback과 Source 연결이 더 강한 증거입니다.

↑ 첫 등장으로

지식 복리

이전 작업에서 얻은 판단이 다음 작업의 출발점이 되어 조사와 판단의 중복을 줄이고 품질 경계를 누적하는 효과입니다. 두 번째 결과에서 첫 판단이 실제로 쓰였다는 근거가 있어야 합니다.

↑ 첫 등장으로

지식 자산

다음 사람이나 에이전트가 다시 찾고 적용할 수 있도록 근거, scope, 상태, 연결을 갖춘 지식입니다. 단순한 대화 기록이나 출처 없는 요약과 구분합니다.

↑ 첫 등장으로
