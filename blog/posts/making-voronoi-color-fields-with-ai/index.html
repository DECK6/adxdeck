AI와 만드는 보로노이, 가까운 점으로 색면 나누기

AI와 함께 p5.js로 가까운 기준점의 색을 칠하는 보로노이 패턴을 만듭니다. 직접 실행한 코드로 시드와 점의 수, 격자 크기를 바꾸며 색면의 구도와 경계를 조절합니다.

media-artgenerative-artcreative-codingp5jsAI

표지는 GPT Image 2로 만든 개념 이미지입니다. 아래 코드의 실행 화면은 본문에 따로 실었습니다.

큰 색면 몇 개가 맞닿은 그림을 만들려면 경계선을 어디에 놓아야 할까요. 선을 하나씩 그리는 대신 화면에 점을 놓고, 각 위치에서 가장 가까운 점을 찾게 할 수 있습니다. 점마다 색을 정하면 거리의 차이가 면의 경계로 드러납니다. 보로노이 패턴을 만드는 출발점입니다.

이번에는 AI에게 이 규칙을 p5.js 코드로 옮기게 하고, 결과를 직접 확인하는 작은 제작 과정을 다룹니다. 생성형 AI는 코드 초안과 설명을 돕습니다. 실행 중인 그림은 점의 좌표와 거리 계산으로 만들어집니다. 캔버스를 다시 그릴 때마다 이미지 생성 모델에 요청하는 방식은 아닙니다.

가까운 점을 찾는 조건부터 요청하기

D3의 공식 보로노이 설명은 각 기준점에 가장 가까운 위치들을 하나의 영역으로 묶습니다. 여기서는 그 정의를 작은 정사각형 격자 위에서 구현합니다. 각 칸의 중심에서 모든 기준점까지 거리를 비교하고, 가장 가까운 점의 색으로 칸 전체를 채웁니다. 완성된 경계에는 격자 크기에 따른 계단이 남습니다. 정확한 다각형 꼭짓점을 구하는 벡터 구현과 구분해서 보아야 합니다.

AI에게는 '보로노이처럼 보이는 그림'만 요청하기보다, 칠할 색을 결정하는 방법까지 적어 주는 편이 좋습니다. 예를 들어 다음과 같이 시작합니다.

p5.js 2.3.1로 정적인 보로노이 색면을 만들어 주세요.
캔버스는 960×540, 기준점은 12개, 시드는 24로 시작합니다.
화면을 한 변 6픽셀의 정사각형 격자로 나누세요.
각 칸의 중심에서 모든 기준점까지의 거리 제곱을 비교하고,
가장 가까운 점의 팔레트 색으로 칸을 채우세요.
거리가 같으면 배열에서 먼저 나온 점을 선택하세요.
기준점은 작은 검은 원으로 표시합니다.
시드와 점의 수, 격자 크기는 cfg에 모으세요.
외부 이미지와 보로노이 라이브러리는 쓰지 마세요.
이 그림이 격자로 근사한 결과라는 점도 설명해 주세요.

거리 제곱을 비교해도 가장 가까운 점의 순서는 같습니다. 두 좌표의 차이를 각각 제곱해 더한 뒤, 비교할 때마다 제곱근을 구하는 과정을 생략합니다. 같은 거리는 먼저 나온 점에 남겨 두도록 정해 둡니다. 이 조건으로 같은 거리의 칸도 일관되게 칠할 수 있습니다.

두 파일로 색면 만들기

빈 폴더에 index.html과 sketch.js를 만듭니다. 이 예제는 p5.js 2.3.1을 고정해서 사용하며, 라이브러리를 처음 불러올 때 인터넷 연결이 필요합니다. index.html에는 다음 내용을 넣습니다.

<!doctype html>
<html lang="ko">
<meta charset="utf-8">
<title>Voronoi color field demo</title>
<style>
  body { margin: 0; background: #e9dfcd; }
  canvas { display: block; }
</style>
<script src="https://cdn.jsdelivr.net/npm/p5@2.3.1/lib/p5.min.js"></script>
<script src="sketch.js"></script>
</html>

sketch.js에는 아래 코드를 넣습니다. 데이터는 설정을 담은 cfg, 색 목록인 palette, 기준점 좌표를 담은 sites로 나눕니다. 점을 만드는 단계와 그 점들을 이용해 칠하는 단계를 분리해 두면, 구도가 바뀐 원인을 확인하기 쉽습니다.

const cfg = { seed: 24, count: 12, cell: 6 };
const palette = ['#e3ba92', '#b96c50', '#355e63', '#79979a', '#e9dfcd'];
let sites = [];

function setup() {
  createCanvas(960, 540);
  pixelDensity(1);
  randomSeed(cfg.seed);
  for (let i = 0; i < cfg.count; i++) {
    sites.push({ x: random(width), y: random(height) });
  }
  noLoop();
}

function draw() {
  noStroke();
  for (let y = 0; y < height; y += cfg.cell) {
    for (let x = 0; x < width; x += cfg.cell) {
      const cx = x + cfg.cell / 2;
      const cy = y + cfg.cell / 2;
      let nearest = 0;
      let best = Infinity;
      for (let i = 0; i < sites.length; i++) {
        const dx = cx - sites[i].x;
        const dy = cy - sites[i].y;
        const d2 = dx * dx + dy * dy;
        if (d2 < best) {
          best = d2;
          nearest = i;
        }
      }
      fill(palette[nearest % palette.length]);
      rect(x, y, cfg.cell, cfg.cell);
    }
  }
  fill('#172c31');
  for (const p of sites) circle(p.x, p.y, 5);
}

두 파일이 있는 폴더에서 터미널을 열어 다음 명령을 실행합니다. 브라우저에서 http://localhost:8000/을 열면 됩니다. 이 명령에는 Python 3가 필요합니다.

python3 -m http.server 8000

기본 설정에서는 12개의 작은 점과 모래색·적갈색·청록색 계열의 면이 나타납니다. noLoop()가 반복 그리기를 멈추므로 화면은 정지해 있습니다. 설정을 바꿔 파일을 저장한 뒤 페이지를 새로고침하면 새 결과를 볼 수 있습니다.

본문 코드의 실제 실행 화면입니다. 960×540 캔버스에 한 변 6픽셀인 칸을 칠했습니다.

같은 색이 맞닿으면 두 영역이 하나처럼 보일 수 있습니다. 위 코드는 다섯 색을 순서대로 반복해서 쓰므로, 기준점 12개가 서로 다른 12색으로 보이는 것은 아닙니다. 검은 점을 함께 표시한 이유도 여기에 있습니다. 각 영역을 뚜렷이 구분하려면 팔레트에 서로 구별되는 색을 더 넣고 비교해 보세요.

시드와 점의 수를 따로 바꾸기

먼저 seed만 24에서 25로 바꾸고 새로고침합니다. 색 목록과 점의 수는 그대로 둔 채 점의 배치가 달라집니다. 큰 면이 화면 가장자리를 차지하는지, 작은 면들이 특정 위치에 모이는지 비교해 보세요. 마음에 드는 구도를 찾으면 그 시드를 기록합니다. p5.js의 randomSeed 문서는 같은 시드로 난수열을 재현하는 방법을 설명합니다. 코드와 라이브러리 버전도 함께 보관해야 같은 제작 조건을 다시 만들 수 있습니다.

다음에는 시드를 24로 되돌리고 count를 12에서 6으로 줄입니다. 이 코드에서는 좌표를 같은 순서로 뽑으므로 처음 여섯 점이 남습니다. 빠진 점이 차지하던 곳을 남은 점들이 나누어 가지면서 넓은 색면이 생깁니다. 점을 무작정 늘리는 것보다, 넓은 면이 그림 안에서 얼마나 오래 시선을 붙잡게 할지 먼저 판단해 보세요.

random(width)와 random(height)는 각각 가로와 세로 범위에서 좌표를 고릅니다. random 공식 문서에 따르면 상한은 포함하지 않습니다. 이 배치는 점 사이의 최소 간격을 보장하지 않아서 가까이 붙은 점도 생깁니다. 균등한 크기의 타일을 기대하면 결과가 어색할 수 있습니다. 여기서는 큰 면과 작은 면이 섞인 구도로 받아들이고, 시드를 바꾸며 그 배치를 고릅니다.

마지막으로 cell을 6에서 12로 바꿉니다. 점의 위치는 그대로이고 경계의 계단이 굵어집니다. 기본 화면은 160×90칸인 14,400칸을 칠하지만, 12픽셀 격자는 80×45칸인 3,600칸을 칠합니다. 이는 계산할 칸의 수이며, 실행 시간이 정확히 네 배 줄어든다는 뜻은 아닙니다. 더 매끄러운 경계를 보고 싶으면 3으로 낮출 수 있습니다. 처음에는 캔버스 양쪽 길이를 나누어떨어지게 하는 양의 정수 3, 6, 12 안에서 비교하고, count도 1 이상의 정수로 유지하세요.

AI가 만든 그림에서 확인할 부분

이 글의 코드는 브라우저의 p5.js 2.3.1에서 실행했습니다. 기본 설정을 두 번 그렸을 때 캔버스 픽셀이 같았고, 시드 25와 기준점 6의 결과는 기본 화면과 달랐습니다. cell: 12도 따로 실행했습니다. 색면은 기준점을 표시한 원 주변을 제외한 격자 중심의 픽셀 색을 독립적인 거리 계산과 비교했습니다. 눈으로 무늬만 확인하는 것보다, '가까운 점의 색을 칠했는가'를 직접 확인하는 검사입니다.

규칙을 검토할 때는 점 두 개만 남겨 보는 방법도 유용합니다. (240, 270)과 (720, 270)을 기준점으로 놓으면 좌우의 중간인 x = 480을 경계로 나뉘어야 합니다. 두 점을 대각선에 놓으면 경계도 기울어집니다. 이 예제의 거리 계산은 이런 배치와 같은 거리인 경우를 별도 검사했습니다. 원하는 모습과 다른 결과가 나오면 AI에게 전체 코드를 다시 작성하게 하기 전에, 이 작은 경우에서 어떤 칸을 잘못 칠하는지 먼저 보여 주세요.

기본 설정의 계단 경계는 오류가 아니라 이번 표현 방식에서 정한 해상도입니다. 픽셀에 가까운 거친 면을 유지할지, 더 작은 격자로 매끄럽게 만들지 선택할 수 있습니다. 큰 인쇄물에서 선명한 다각형 경계가 필요하다면 D3처럼 셀의 다각형을 구하는 구현을 다음 단계로 검토할 수 있습니다. 그 방식의 제작과 출력은 이번 예제에서 실행한 범위에 포함하지 않습니다.

한 장을 고를 때는 색을 바꾸기 전에 점의 배치부터 비교해 보세요. 이번 그림에서 바꾸는 것은 AI에게 건네는 분위기 묘사뿐 아니라, 면을 나누는 좌표와 규칙입니다. 마음에 드는 구도를 시드로 남겨 두면 색과 경계의 거칠기를 같은 구도 위에서 차분히 조정할 수 있습니다.
