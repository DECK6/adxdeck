# AI와 만드는 서클 패킹, 원 사이의 여백 설계하기

![크기가 다른 청록색과 주황색 원 사이로 밝은 여백이 흐르는 서클 패킹 개념 표지](images/circle-packing-cover.png)

*표지는 GPT Image 2로 만든 개념 이미지입니다. 본문에는 아래 코드를 실행한 화면을 따로 실었습니다.*

원들을 화면에 흩뿌리면 금세 서로 겹칩니다. 겹침을 없애려고 같은 크기의 원을 격자에 놓으면 이번에는 너무 고른 무늬가 됩니다. 크기는 제각각이면서 서로 침범하지 않는 배치를 만들 수 있을까요. 이번에는 무작위로 중심을 고른 뒤, 그 자리에 들어갈 수 있는 크기를 계산하는 서클 패킹을 만들어 봅니다.

여기서 AI는 조건을 코드로 옮기고 오류를 찾는 제작 보조자입니다. 그림을 만드는 규칙은 좌표와 거리 계산으로 정해집니다. 실행할 때마다 이미지 생성 모델을 호출하지 않습니다. 이 차이를 이해하면 AI에게 분위기를 묘사하는 데서 더 나아가, 직접 바꿔 볼 수 있는 작품의 규칙을 요청할 수 있습니다.

## 원의 크기보다 남겨 둘 간격을 먼저 정하기

이번 방식은 원을 하나씩 배치합니다. 새 중심에서 캔버스 가장자리까지의 거리와 이미 놓인 원들까지의 거리를 구한 다음, 가장 작은 허용 반지름을 고릅니다. 반지름이 너무 작으면 그 중심은 버리고 다음 후보를 뽑습니다. 앞서 놓인 원을 밀거나 줄이지 않으므로, 먼저 선택된 위치가 뒤의 배치에 영향을 줍니다.

두 원의 중심 사이 거리가 `d`, 먼저 놓인 원의 반지름이 `R`, 남기려는 간격이 `gap`이면 새 원의 반지름은 `d - R - gap`을 넘을 수 없습니다. 중심 사이가 50픽셀이고 기존 반지름이 20픽셀, 간격이 4픽셀이면 새 반지름은 최대 26픽셀입니다. 이 조건을 모든 기존 원에 적용합니다. 화면 가장자리에는 별도의 `margin`을 둡니다. 원 사이 통로와 그림 바깥 테두리의 여백을 따로 다루기 위해서입니다.

AI에게는 다음처럼 제작 조건을 전달할 수 있습니다. 이 프롬프트는 원하는 형태뿐 아니라 확인할 계산을 함께 적은 예시입니다.

```text
p5.js 2.3.4로 정적인 서클 패킹을 만들어 주세요.
960×540 캔버스, 시드 24, 후보 중심 1200회로 시작합니다.
후보 중심을 무작위로 뽑고, 화면 경계와 기존 원까지의
거리를 이용해 들어갈 수 있는 최대 반지름을 계산하세요.
원 사이 간격은 4픽셀, 바깥 여백은 24픽셀입니다.
반지름은 최대 64픽셀로 제한하고, 4픽셀 미만이면 버리세요.
이미 배치한 원은 움직이지 않습니다. 외곽선 없이 색으로 채우세요.
설정은 cfg에 모으고, 거리 계산과 배치 함수를 분리해 주세요.
후보 수와 최종 원의 수가 다른 이유도 설명해 주세요.
```

이 방법은 가능한 자리를 순서대로 채우는 간단한 규칙입니다. 빈 공간을 모두 없애거나 가장 높은 밀도를 보장하는 최적화는 아닙니다. 이번 작업에서는 남은 공간도 그림의 재료로 봅니다. 원의 수가 많아졌다는 이유만으로 더 좋은 결과라고 판단하지 않습니다.

## 두 파일로 만들고 실제 화면 확인하기

빈 폴더에 `index.html`과 `sketch.js`를 만듭니다. [p5.js 공식 다운로드 안내](https://p5js.org/download/)에서 확인한 2.3.4를 사용합니다. 아래 HTML은 그 버전을 고정해 불러오며, 처음 라이브러리를 읽을 때 인터넷 연결이 필요합니다.

```html
<!doctype html>
<html lang="ko">
<meta charset="utf-8">
<title>Circle packing demo</title>
<style>
  body { margin: 0; background: #f1e8d7; }
  canvas { display: block; }
</style>
<script src="https://cdn.jsdelivr.net/npm/p5@2.3.4/lib/p5.min.js"></script>
<script src="sketch.js"></script>
</html>
```

`sketch.js`에는 다음 코드를 넣습니다. `availableRadius()`는 주어진 중심에서 허용되는 반지름을 반환합니다. `packCircles()`는 후보를 반복해서 뽑고, 최소 크기를 만족한 원만 배열에 담습니다. 계산과 그리기를 나눠 두면 배치가 잘못된 것인지, 화면에 표시하는 크기가 잘못된 것인지 확인하기 쉽습니다.

```javascript
const cfg = {
  seed: 24, attempts: 1200,
  minR: 4, maxR: 64, gap: 4, margin: 24
};
const palette = ['#214f52', '#c76846', '#dca55a', '#71948a'];
let disks = [];

function availableRadius(x, y, placed, opt, w, h) {
  let r = Math.min(opt.maxR,
    x - opt.margin, w - opt.margin - x,
    y - opt.margin, h - opt.margin - y);
  for (const c of placed) {
    const distance = Math.hypot(x - c.x, y - c.y);
    r = Math.min(r, distance - c.r - opt.gap);
  }
  return r;
}

function packCircles(w, h, opt, rand) {
  const placed = [];
  for (let i = 0; i < opt.attempts; i++) {
    const x = rand(opt.margin, w - opt.margin);
    const y = rand(opt.margin, h - opt.margin);
    const r = availableRadius(x, y, placed, opt, w, h);
    if (r >= opt.minR) placed.push({ x, y, r });
  }
  return placed;
}

function setup() {
  createCanvas(960, 540);
  pixelDensity(1);
  randomSeed(cfg.seed);
  disks = packCircles(width, height, cfg, (a, b) => random(a, b));
  noLoop();
}

function draw() {
  background('#f1e8d7');
  noStroke();
  for (let i = 0; i < disks.length; i++) {
    const c = disks[i];
    fill(palette[i % palette.length]);
    circle(c.x, c.y, c.r * 2);
  }
}
```

두 파일이 있는 폴더의 터미널에서 다음 명령을 실행한 뒤 브라우저로 `http://localhost:8000/`을 엽니다. 이 실행 방법에는 Python 3가 필요합니다.

```bash
python3 -m http.server 8000
```

화면에는 따뜻한 바탕 위로 청록색·적갈색·황토색·회녹색 원들이 나타납니다. 기본 설정을 실행한 결과는 아래와 같습니다. `noLoop()`를 사용하므로 정지 이미지이며, 값을 바꾸고 파일을 저장한 뒤 새로고침하면 새로운 배치를 볼 수 있습니다.

![시드 24로 1200개의 후보를 검사해 배치한 217개의 원](images/circle-packing-frame.png)

*본문 코드의 실제 960×540 캔버스입니다. 원 사이 간격은 최소 4픽셀, 바깥 여백은 최소 24픽셀로 계산했습니다.*

계산에는 반지름을 쓰지만 `circle()`의 세 번째 인수에는 지름을 넣습니다. 그래서 마지막에 `c.r * 2`를 전달합니다. [공식 circle 문서](https://p5js.org/reference/p5/circle/)도 이 인수를 지름으로 설명합니다. 이 곱셈이 빠지면 겹치지는 않더라도 의도한 것보다 작은 원과 넓은 빈틈이 생깁니다. 겹침 여부만 검사해서는 놓치기 쉬운 부분입니다.

## 숫자 하나씩 바꾸며 여백 고르기

처음에는 `seed`만 `24`에서 `25`로 바꿔 보세요. 원을 놓는 규칙은 그대로이고, 후보 중심의 순서가 달라집니다. 큰 원이 어느 위치에 놓이는지, 작은 원들이 어느 틈에 모이는지 비교합니다. [randomSeed 문서](https://p5js.org/reference/p5/randomSeed/)는 같은 시드로 난수열을 재현하는 방법을 설명합니다. 다시 만들고 싶은 그림은 시드뿐 아니라 코드와 p5.js 버전, 나머지 설정도 함께 남겨 두세요.

다음에는 기본 시드로 돌아와 `gap`을 `4`에서 `10`으로 바꿉니다. 원 사이에 남겨야 할 간격이 커져 밝은 바탕이 더 많이 드러납니다. 다만 기존 그림의 원들을 일괄적으로 줄인 결과는 아닙니다. 앞의 원 크기와 후보의 채택 여부가 달라지고, 그 차이가 뒤의 계산에도 이어집니다. 같은 시드를 쓰더라도 여러 원의 크기와 개수가 함께 바뀔 수 있습니다.

아래는 한 번에 한 설정만 바꾸고 실제로 실행한 결과입니다. 원의 수는 이 코드와 버전, 지정한 설정에서 관측한 값입니다.

| 바꾼 설정 | 배치된 원 | 비교할 부분 |
|---|---:|---|
| 기본값 | 217개 | 큰 원과 작은 원의 크기 대비 |
| `seed: 25` | 209개 | 큰 원의 위치와 틈의 모양 |
| `gap: 10` | 154개 | 원 사이로 드러나는 바탕 |
| `maxR: 32` | 280개 | 큰 원이 줄어든 화면의 리듬 |
| `attempts: 300` | 104개 | 덜 채워진 공간과 초기 배치 |
| `minR: 8` | 150개 | 작은 점들을 덜어 낸 질감 |

`attempts`는 원의 개수가 아니라 후보 중심을 뽑는 횟수입니다. [random 문서](https://p5js.org/reference/p5/random/)에서 설명하는 범위 난수로 중심을 뽑지만, 이미 찬 곳이나 너무 좁은 틈의 후보는 버립니다. 이 코드에서는 각 시도마다 좌표 두 개만 뽑습니다. 따라서 다른 설정이 같으면 시도 횟수만 늘릴 때 앞서 배치한 원은 남고, 뒤의 후보가 추가됩니다. 색을 무작위로 고르는 코드를 중간에 넣으면 난수 소비 순서도 바뀌므로 이 비교 조건도 다시 확인해야 합니다.

처음에는 표의 값 안에서 하나씩 바꿔 보세요. 더 확장할 때는 `minR`를 양수로, `maxR`를 그 이상으로 유지하고 `gap`은 음수로 두지 않습니다. `attempts`는 0 이상의 정수로 사용합니다. 이 캔버스의 `margin`은 0 이상 270 미만이어야 안쪽 높이가 남습니다. 후보마다 이전 원들을 모두 검사하므로 시도 횟수를 크게 늘리면 계산량도 커집니다. 한 번에 수십만 번으로 올리기보다 작은 비교부터 시작하는 편이 좋습니다.

## AI 코드에서 규칙과 표현을 함께 확인하기

AI가 만든 코드를 검토할 때는 먼저 작은 경우를 살펴봅니다. 중심 간 거리가 50픽셀인 두 원에서 기존 반지름 20, 간격 4를 지정하면 새 반지름이 26을 넘지 않아야 합니다. 새 중심이 기존 원 안에 있으면 허용 반지름이 음수가 될 수 있는데, 이 후보를 버리는 것이 정상입니다. 화면 경계에 너무 가까운 후보도 같은 방식으로 제외합니다.

이 글의 예제는 별도 검사에서 경계·이웃 원·대각선 거리·최대 반지름·최소 크기의 채택과 거부를 확인했습니다. 실제 브라우저의 p5.js 2.3.4에서는 표의 모든 설정을 실행하고, 배치된 모든 원 쌍의 간격과 화면 여백을 검사했습니다. 기본 설정을 두 번 그렸을 때 픽셀이 같았고, 원의 중심과 충분히 큰 원의 내부 픽셀은 지정한 팔레트 색과 일치했습니다. 작은 원의 가장자리에는 안티앨리어싱으로 색이 섞일 수 있어 내부 픽셀과 구분했습니다. 영상 저장이나 대형 인쇄 출력까지 검증한 예제는 아닙니다.

형태가 정상적으로 그려져도 작품의 판단은 남습니다. 큰 원 몇 개가 시선을 잡아 주는 화면이 필요한지, 비슷한 크기의 원들이 잔잔하게 반복되는 화면이 필요한지 먼저 고릅니다. 빈틈이 아쉽다고 시도 횟수만 늘리면 작은 점들이 화면을 분주하게 만들 수 있습니다. 반대로 `minR`를 올리면 가는 질감이 사라지는 대신 큰 형태 사이의 간격이 읽히기 쉬워질 수 있습니다.

마음에 드는 시드에서 바탕색을 바꾸면 원 사이 공간의 인상도 달라집니다. 어두운 바탕은 원을 따로 떠 있는 물체처럼 보이게 할 수 있고, 밝은 바탕은 사이의 통로를 드러낼 수 있습니다. AI에게 다음 수정을 요청할 때도 '더 예쁘게' 대신 '배치는 보존하고 바탕과 원의 대비만 비교하게 해 달라'고 범위를 좁혀 보세요. 원을 채우는 규칙을 이해하면, 채우지 않을 공간도 직접 설계할 수 있습니다.
