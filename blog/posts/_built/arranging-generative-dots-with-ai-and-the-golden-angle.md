# 회전각 하나로 달라지는 점의 무늬, AI와 만드는 황금각 배열

![짙은 남색 바탕에 청록색과 산호색 점들이 나선형 원반을 이루는 개념 이미지](images/golden-angle-cover.png)

*표지는 GPT Image 2로 생성한 개념 이미지입니다. 아래 비교 화면은 본문 코드의 실제 실행 결과입니다.*

작은 점을 많이 찍는다고 화면이 고르게 채워지지는 않는다. 점을 하나 추가할 때마다 중심에서 조금 멀어지고 일정한 각도만큼 회전하게 해 보자. 어떤 각도에서는 점이 몇 개의 선 위에 겹치고, 어떤 각도에서는 원반을 가로지르는 나선 무늬가 나타난다. 같은 점 개수와 반지름을 유지해도 **다음 점을 어느 방향에 놓느냐**에 따라 화면에서 느껴지는 리듬이 달라진다.

이번 결과물은 세 회전각을 나란히 비교하는 정지 이미지다. AI에는 좌표 계산과 검사 코드를 맡길 수 있지만, 최종 배열은 난수도 이미지 생성 모델도 사용하지 않는다. 입력한 수학 규칙이 점의 위치를 정한다. 생성형 AI를 제작 보조로 쓰는 일과 알고리즘으로 제너러티브 이미지를 만드는 일을 이렇게 구별하면, 결과가 마음에 들지 않을 때 고칠 변수를 찾기 쉽다.

## 점의 방향과 중심에서의 거리를 따로 설계한다

점 번호를 0부터 세고, 번호에 회전각을 곱해 방향을 정한다. 120도씩 돌면 방향은 0도, 120도, 240도를 거쳐 다시 처음으로 돌아온다. 거리는 계속 늘어나지만 방향은 세 가지이므로 점들은 세 갈래의 선에 모인다. 원반처럼 보이지 않아도 계산이 실패한 것은 아니다. 선택한 규칙이 그대로 드러난 결과다.

거리를 정하는 방식도 중요하다. 반지름을 일정하게 늘리면 바깥쪽의 더 넓은 띠에 같은 수의 점이 놓여 중심부가 상대적으로 조밀해진다. 이 예제에서는 최대 반지름을 `R`, 전체 점 수를 `N`, 점 번호를 `i`라고 할 때 거리를 `R * sqrt((i + 0.5) / N)`으로 계산한다. 원의 넓이가 반지름의 제곱에 비례하므로, 반지름 제곱을 같은 간격으로 나누는 방식이다. `0.5`는 각 구간의 중간을 택해 첫 점이 정확히 중심에 겹치지 않도록 한다.

이 공식만으로 모든 각도에서 점들이 고르게 퍼지지는 않는다. 중심에서 얼마만큼 떨어질지는 정하지만, 같은 방향에 몰리는 문제는 회전각이 결정한다. 또 이웃한 점 사이의 거리를 일정하게 만드는 공식도 아니다. 점의 겹침을 반드시 막아야 하는 작업이라면 최소 거리나 충돌 조건을 별도로 넣어야 한다.

세 번째 패널에는 황금각을 사용한다. 황금비를 `φ = (1 + sqrt(5)) / 2`로 두면 작은 쪽 황금각은 `360 / φ²`, 즉 `180 * (3 - sqrt(5))`도다. 약 137.507764도이며, 코드에서는 반올림한 상수 대신 식으로 계산한다. 수학적으로 한 바퀴에 대한 비율이 무리수라 유한한 횟수 뒤에 같은 방향으로 정확히 돌아오는 각도가 아니다. 실제 컴퓨터에서는 유한한 정밀도의 근삿값으로 계산한다.

가운데의 137.5도는 이와 가깝지만, 한 바퀴의 `55 / 144`이므로 수학적으로 144번마다 같은 방향을 다시 지난다. 작은 차이가 계속 누적될 때 화면이 어떻게 달라지는지 비교할 수 있다. 그렇다고 황금각이 언제나 가장 아름답거나 모든 배치 문제에서 최적이라는 뜻은 아니다. 이 글의 목표는 식물의 성장 과정을 재현하거나 자연의 효율을 증명하는 것이 아니라, 반복하는 각도를 조형 변수로 다루는 것이다.

## AI에게 그림의 이름보다 좌표 규칙을 전달한다

“해바라기 같은 그림을 만들어 줘”라는 요청만으로는 AI가 점의 개수나 배치 원리를 임의로 바꿀 수 있다. 원하는 비교 조건을 먼저 고정하면 구현과 결과를 대조하기 쉽다. 다음은 제작을 시작할 때 사용할 수 있는 요청 예시다.

```text
p5.js 2.4.0으로 960×540 정지 화면을 만들어라.
각 패널에 점 1200개, 최대 반지름 135, 점 지름 3.6을 사용한다.
회전각 120도, 137.5도, 180*(3-sqrt(5))도를 나란히 비교한다.
점 번호 i는 0부터 시작하며 거리는 R*sqrt((i+0.5)/N)이다.
각도는 i*회전각이고 삼각함수에 넣기 전에 라디안으로 변환한다.
순수 좌표 함수와 p5.js 화면 코드를 분리하고 난수는 쓰지 마라.
S키로 PNG를 저장하게 해라.
점 1개의 거리, 90도씩 도는 점의 방향, 반지름 제곱의 간격,
120도에서 세 방향 반복, 음수 각도와 잘못된 입력을 검사해라.
```

브라우저와 텍스트 편집기를 준비한다. [공식 다운로드 페이지](https://p5js.org/download/)에서 확인한 p5.js 2.4.0으로 실행했다. 빈 폴더에 `index.html`, `spiral.js`, `sketch.js`를 만들고 아래 내용을 각각 저장한다. HTML이 고정 버전 CDN에서 라이브러리를 읽으므로 인터넷 연결이 필요하다. AI API 키나 별도 이미지 파일은 필요 없다.

`spiral.js`는 중심을 원점으로 한 좌표만 반환한다. 점 개수는 양의 정수, 반지름은 양의 유한한 수, 회전각은 유한한 수를 받는다. `Math.sin()`과 `Math.cos()`에는 라디안을 넣는다. 도 단위 값을 그대로 넣어도 그럴듯한 무늬가 나올 수 있으므로, 화면만 보고 변환이 맞았다고 판단하지 않는 편이 좋다.

```js
function spiralPoints(count, radius, degrees) {
  if (!Number.isInteger(count) || count < 1 ||
      !Number.isFinite(radius) || radius <= 0 || !Number.isFinite(degrees)) {
    throw new RangeError('Use a positive integer count, positive radius and finite angle.');
  }
  const step = degrees * Math.PI / 180;
  return Array.from({ length: count }, (_, i) => {
    const r = radius * Math.sqrt((i + 0.5) / count);
    const theta = i * step;
    return { x: r * Math.cos(theta), y: r * Math.sin(theta) };
  });
}
```

`sketch.js`는 좌표를 각 패널의 중심으로 옮기고 같은 지름의 원을 그린다. 색은 점 번호에 따라 청록색에서 산호색으로 바뀐다. 번호가 커질수록 중심에서 멀어지므로 색 변화도 중심과 바깥쪽의 관계를 보여 준다. [noLoop](https://p5js.org/reference/p5/noLoop/)는 반복 그리기를 멈추는 함수다. 여기서는 모든 그림을 `setup()`에서 한 번 그리며, 이후 애니메이션으로 확장할 때에도 정지 화면이라는 출발 조건을 분명하게 해 둔다.

```js
const COUNT = 1200;
const RADIUS = 135;
const DIAMETER = 3.6;
const GOLDEN_ANGLE = 180 * (3 - Math.sqrt(5));
const ANGLES = [120, 137.5, GOLDEN_ANGLE];

function setup() {
  createCanvas(960, 540);
  pixelDensity(1);
  noLoop();
  background('#101421');
  textFont('monospace');
  textSize(14);
  noStroke();
  const labels = ['120 DEG', '137.5 DEG', 'GOLDEN ANGLE'];
  ANGLES.forEach((angle, panel) => {
    const cx = 168 + panel * 312, cy = 270;
    fill('#ded9cf');
    text(labels[panel], cx - 135, 95);
    const points = spiralPoints(COUNT, RADIUS, angle);
    points.forEach((p, i) => {
      const t = (i + 0.5) / COUNT;
      fill(lerpColor(color('#4ed9c4'), color('#ff9b72'), t));
      circle(cx + p.x, cy + p.y, DIAMETER);
    });
  });
  fill('#a3adbf');
  text('1200 POINTS / RADIUS 135 / DOT 3.6', 33, 456);
  text('S: SAVE PNG', 33, 482);
}

function keyPressed() {
  if (key === 's' || key === 'S') saveCanvas('golden-angle', 'png');
}
```

Python 3가 있다면 파일을 저장한 폴더에서 다음 명령을 실행하고 `http://localhost:8000/`을 연다. 실행을 마치면 터미널에서 Ctrl+C로 서버를 끝낸다. 화면을 클릭한 뒤 S키를 누르면 [saveCanvas](https://p5js.org/reference/p5/saveCanvas/)로 PNG 저장을 요청한다. 브라우저에 따라 바로 내려받거나 저장 대화상자가 열린다. 캔버스의 픽셀 밀도를 1로 고정해 저장 이미지의 크기는 960×540이다.

```bash
python3 -m http.server 8000
```

## 작은 각도 차이는 쌓이고, 점 크기는 틈을 바꾼다

실제 화면에서 120도 배열은 점보다 세 갈래의 선으로 읽힌다. 바깥쪽으로 갈수록 같은 방향의 이웃 점들이 가까워지고, 지름 3.6의 원들이 겹치기 때문이다. 나머지 두 패널에서는 개별 점과 그 사이의 어두운 틈이 보이며, 눈이 이웃 점을 연결하면서 나선 방향을 읽는다. 코드가 나선 곡선을 선으로 그리는 것은 아니다.

현재 좌표에서 점 쌍 사이의 거리를 직접 계산하면 다음과 같다. 여기서 최소 거리는 점 중심 사이의 유클리드 거리이며, 이번 1200개 배열에서 관측한 값이다. 모든 설정에 대한 보장값은 아니다.

| 회전각 | 점 개수 | 중심 거리 67.5 안쪽의 점 | 최소 점 중심 거리 |
|---|---:|---:|---:|
| 120도 | 1200 | 300 | 약 0.169 |
| 137.5도 | 1200 | 300 | 약 6.024 |
| 황금각, 약 137.507764도 | 1200 | 300 | 약 6.025 |

반지름이 절반인 원은 전체 원반 넓이의 4분의 1이다. 세 배열 모두 안쪽 점이 300개인 것은 같은 반지름 규칙을 썼기 때문이다. 이 수가 같아도 왼쪽 패널의 방향 분포는 전혀 다르다. 면적에 따른 반지름 분배와 평면에서의 이웃 관계를 나누어 보면, 왜 하나의 “균일함”이라는 말만으로는 화면을 설명하기 어려운지 알 수 있다.

두 원반의 최소 거리 차이는 이번 설정에서는 작다. 차이가 더 잘 보이는 곳은 점들이 만드는 연결 방향과 무늬다. 마지막 점의 번호는 1199이므로, 137.5도와 황금각의 누적 방향 차이는 약 9.31도에 이른다. 처음의 각도 차이가 작아도 모든 점이 같은 위치에 놓이는 것은 아니다. 다만 이 결과만으로 큰 해상도나 다른 점 개수에서도 어느 쪽이 더 낫다고 결론 내릴 수는 없다.

처음 변형할 때에는 `DIAMETER`만 바꾸는 편이 좋다. 점 중심은 유지되므로 점 자체의 크기가 틈과 덩어리의 인상을 어떻게 바꾸는지 비교할 수 있다. 그다음 `COUNT`를 바꾸면 같은 원반 안의 밀도가 달라진다. 이 코드에서는 전체 점 수가 거리 공식의 분모에 들어가므로, 점을 늘릴 때 기존 점의 위치까지 다시 계산된다. 이미 놓은 점을 유지한 채 바깥에만 추가하는 성장 애니메이션은 아니다.

`RADIUS`는 원반의 크기를 바꾼다. 너무 키우면 패널끼리 겹치거나 화면 밖으로 나가므로 배치 간격도 함께 확인해야 한다. `ANGLES`의 값을 바꿀 때에는 `labels`도 고치고, 점 개수·반지름·지름을 바꿨다면 화면 아래의 안내 문자열도 같은 값으로 수정한다. 예제의 라벨은 비교 조건을 보여 주기 위해 고정 문자열로 적었다.

## AI 코드의 그럴듯한 무늬를 작은 좌표로 검증한다

황금각이라는 이름이나 복잡한 원반 모양은 코드가 맞다는 증거가 되지 않는다. 각도 변환을 빼먹거나 반지름에 제곱근을 쓰지 않아도 화면에는 다른 질서가 나타난다. 그래서 큰 그림을 보기 전에 점을 아주 적게 놓는 검사를 함께 했다.

점이 하나일 때 중심 거리는 최대 반지름을 제곱근 2로 나눈 값이어야 한다. 네 점을 90도씩 회전시키면 오른쪽·아래·왼쪽·위 방향으로 놓여야 한다. 반지름 제곱은 일정한 간격으로 증가하고, 120도에서는 세 점 뒤에 같은 방향으로 돌아와야 한다. 음수 회전각은 같은 번호의 점을 가로축 기준으로 뒤집으며, 같은 입력을 반복하면 같은 좌표가 나와야 한다. 이 조건들과 잘못된 입력을 포함한 계산 검사 6개가 통과했다.

브라우저에서는 세 기본 배열과 점 개수·중심 거리 분포를 확인하고 PNG 저장 및 새로고침 결과를 대조했다. 서로 다른 브라우저나 글꼴 환경까지 이미지 바이트가 같다는 검증은 아니다. 또한 이번 결과물은 정지 화면이다. 실시간 공연용 애니메이션, 대형 출력의 처리 시간, 점 충돌 방지, 식물 성장 시뮬레이션은 구현하거나 검증하지 않았다.

완성된 원반을 작품으로 발전시킬 때에는 회전각을 계속 바꾸는 것만이 답은 아니다. 각도를 고정한 채 점의 크기나 색 범위를 바꾸어도 관객이 읽는 리듬이 달라진다. AI에는 좌표와 변형 코드를 요청하고, 제작자는 어떤 틈을 남기고 어떤 방향을 강조할지 비교한다. 숫자 하나를 바꾸는 행위가 조형 선택이 되는 순간은 그 숫자와 화면의 관계를 설명할 수 있을 때다.
