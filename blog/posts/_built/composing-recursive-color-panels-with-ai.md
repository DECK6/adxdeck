# AI와 만드는 재귀 분할, 색면의 크기로 리듬 짓기

![크기와 비율이 다른 직사각형 색면을 크림색 여백으로 구분한 구성](images/recursive-panels-cover.png)

*표지는 GPT Image 2로 만든 개념 이미지입니다. 아래 실습 결과는 p5.js 코드를 직접 실행해 얻은 화면입니다.*

작은 사각형을 늘린다고 화면에 리듬이 저절로 생기지는 않는다. 모든 칸이 비슷하게 잘게 나뉘면 시선을 둘 곳이 흐려지고, 큰 면만 남으면 변화가 부족해진다. 이번에는 하나의 직사각형을 둘로 나누고, 그 안에서 같은 동작을 반복해 크기가 다른 색면을 만든다. 중요한 선택은 얼마나 많이 나누느냐와 함께 **어디서 나누기를 멈추느냐**에 있다.

재귀 분할은 하나의 큰 영역을 작은 영역들로 되풀이해 나누는 방식이다. 이 예제는 긴 변을 따라 분할 위치를 정하고, 더 나누지 않는 마지막 영역만 그린다. 처음 구획한 큰 구조 안에 작은 차이가 남는다. 불규칙한 격자를 쓰는 포스터, 전시의 색면 배경, 화면 전환용 마스크를 설계할 때 출발점으로 삼을 수 있다.

AI는 이 규칙을 코드로 옮기고 오류를 찾는 조력자로 쓴다. 색면을 실제로 만드는 것은 생성형 이미지 모델이 아니라 좌표·난수·종료 조건으로 구성한 알고리즘이다. 생성형 AI에 코드 설계를 맡기는 일과 알고리즘 기반 제너러티브 아트를 실행하는 일을 구별하면, 결과가 마음에 들지 않을 때 무엇을 바꿀지도 구체적으로 말할 수 있다.

## 한 번 더 나눌지 결정하는 규칙

먼저 960×540 캔버스 안에 바깥 여백을 둔 직사각형을 잡는다. 좌표는 `(32, 32)`, 크기는 `896×476`이다. 가로가 더 길면 좌우로, 세로가 더 길면 위아래로 나눈다. 분할 위치는 긴 변의 30~70% 사이에서 고르되, 양쪽에 최소 크기가 남도록 제한한다. 첫 두 단계에서는 충분한 큰 구조를 만들고, 그다음부터는 일정 확률로 분할을 멈춘다.

재귀 호출은 함수가 자기 자신을 다시 부르는 것이다. 여기서는 부모 직사각형 대신 두 자식 직사각형으로 같은 함수를 호출한다. 끝없이 들어가지 않도록 최대 깊이를 두고, 긴 변을 둘로 나눠 최소 크기를 지킬 수 없을 때도 멈춘다. 중단 확률만 종료 조건으로 두면 운에 따라 지나치게 작은 영역이 생길 수 있으므로, 깊이와 크기 제한을 함께 둔다.

분할과 여백은 따로 다룬다. 계산상 자식 영역들은 부모를 빠짐없이 채운다. 그림을 그릴 때 각 영역의 가장자리를 `gap / 2`만큼 안으로 들여 칸 사이에 `gap` 크기의 틈을 낸다. 이렇게 하면 여백만 바꿔도 분할 좌표가 흔들리지 않는다. 기본 `gap`은 8이고 최소 변 길이는 36이므로, 안쪽 색면의 너비와 높이도 양수로 남는다.

AI에 처음 요청할 때는 분위기와 함께 지켜야 할 기하 조건을 적는다. 다음은 대화형 코딩 도구에 사용할 수 있는 요청 예시다. 특정 서비스에서 이 문장만 넣으면 같은 코드가 나온다는 뜻은 아니다.

```text
p5.js로 직사각형 재귀 분할 작품을 만들고 싶다.
긴 변을 따라 두 영역으로 나누고, 분할 깊이·최소 변 길이·중단 확률을 조절하게 해줘.
자식 영역은 부모 안에 있고 서로 겹치지 않으며, 면적의 합이 부모와 같아야 한다.
여백은 분할 후 그릴 때 적용하고, 색 선택은 모든 분할이 끝난 뒤 실행해줘.
같은 시드와 설정에서는 같은 결과를 재현하고 싶다.
먼저 종료 조건과 영역 좌표가 어떻게 바뀌는지 설명한 뒤 최소 코드를 제시해줘.
```

받은 코드를 살펴볼 때는 오른쪽 자식의 시작점에 분할 너비가 더해졌는지, 아래쪽 자식의 시작점에 분할 높이가 더해졌는지부터 확인한다. 캔버스가 그럴듯하게 채워져도 한 자식이 다른 자식을 가리고 있을 수 있다. AI에게 “더 예쁘게”라고 요청하기 전에 겹침과 빈틈을 따로 검사할 이유다.

## 작은 로컬 페이지에서 실행하기

이 글은 2026년 11월 12일 확인한 p5.js 2.3.4로 실행했다. [공식 다운로드 페이지](https://p5js.org/download/)에서 같은 버전의 `p5.min.js`를 내려받아 빈 폴더에 둔다. 그 폴더에 다음 `index.html`과 이어지는 `sketch.js`를 저장한다. 이렇게 라이브러리 파일을 함께 두면 CDN의 최신 버전 변경에 영향을 덜 받는다.

```html
<!doctype html>
<html lang="ko">
<meta charset="utf-8">
<title>재귀 분할 실습</title>
<script src="p5.min.js"></script>
<script src="sketch.js"></script>
<body></body>
</html>
```

`sketch.js` 전체는 다음과 같다. 색을 고르는 난수는 분할이 끝난 다음 별도의 시드로 시작한다. 따라서 팔레트만 바꾸는 실험이 분할 위치까지 바꾸지는 않는다.

```javascript
const CFG = {
  seed: 31, maxDepth: 6, minSide: 36,
  stopChance: 0.2, gap: 8
};
const COLORS = ['#173f46', '#cd653f', '#dfb45c', '#829a8a', '#e7d8bd'];
let panels = [];

function partition(x, y, w, h, rng, cfg, depth = 0) {
  const vertical = w >= h;
  const length = vertical ? w : h;
  if (depth >= cfg.maxDepth || length < 2 * cfg.minSide ||
      (depth >= 2 && rng() < cfg.stopChance)) {
    return [{ x, y, w, h }];
  }
  const cut = Math.max(cfg.minSide,
    Math.min(length - cfg.minSide, length * (0.3 + 0.4 * rng())));
  if (vertical) {
    return [
      ...partition(x, y, cut, h, rng, cfg, depth + 1),
      ...partition(x + cut, y, w - cut, h, rng, cfg, depth + 1)
    ];
  }
  return [
    ...partition(x, y, w, cut, rng, cfg, depth + 1),
    ...partition(x, y + cut, w, h - cut, rng, cfg, depth + 1)
  ];
}

function setup() {
  createCanvas(960, 540);
  pixelDensity(1);
  noLoop();
  noStroke();
  background('#f5efe3');
  randomSeed(CFG.seed);
  panels = partition(32, 32, 896, 476, () => random(), CFG);
  // Layout is finished before any color draws consume randomness.
  randomSeed(CFG.seed + 1000);
  for (const p of panels) {
    fill(random(COLORS));
    rect(p.x + CFG.gap / 2, p.y + CFG.gap / 2,
      p.w - CFG.gap, p.h - CFG.gap);
  }
  describe('서로 다른 크기의 직사각형 색면과 크림색 여백');
}

function keyPressed() {
  if (key === 's' || key === 'S') saveCanvas('recursive-panels', 'png');
}
```

Python 3가 설치된 환경이라면 파일을 둔 폴더에서 다음 명령을 실행하고 브라우저로 `http://localhost:8000`을 연다. 다른 로컬 정적 서버를 사용해도 된다. 이 예제에는 빌드 도구나 추가 패키지가 필요하지 않다.

```sh
python3 -m http.server 8000
```

`randomSeed()`는 같은 난수열을 다시 시작하게 한다. 다만 같은 시드라도 분할 과정에서 난수를 호출하는 순서나 코드가 달라지면 결과도 달라질 수 있다. 시드뿐 아니라 라이브러리 버전과 설정, 코드도 함께 보관한다. [p5.js의 randomSeed 설명](https://p5js.org/reference/p5/randomSeed/)을 참고할 수 있다.

`rect()`는 기본적으로 왼쪽 위 좌표와 너비·높이로 직사각형을 그린다. 이 예제도 그 좌표 방식을 사용한다. `noLoop()`로 계속 다시 그리는 일을 멈추고, `setup()`에서 한 장을 완성한다. [rect 문서](https://p5js.org/reference/p5/rect/)와 좌표를 대조하면 `gap / 2`의 위치와 `gap`을 빼는 크기가 어떻게 맞물리는지 확인하기 쉽다.

![시드 31로 실행한 19개 색면의 재귀 분할 결과](images/recursive-panels-frame.png)

*위 코드를 실행한 960×540 결과. 시드 31, 최대 깊이 6, 중단 확률 0.2, 여백 8을 사용했습니다.*

기본 설정에서는 색면 19개가 생성됐다. 긴 주황색 면과 넓은 녹색 면이 화면을 잡고, 그 사이의 작은 면들이 시선을 나눈다. 같은 설정을 다시 실행했을 때 좌표가 같았고, 분할 영역의 면적 합은 바깥 여백 안의 원래 영역과 일치했다. 그리기 전 영역끼리 겹치지 않는지도 확인했다. 이 면적 보존은 **여백을 넣기 전 구획**에 대한 말이며, 색칠한 면적에는 틈만큼의 감소가 생긴다.

## 변수 하나가 바꾸는 화면의 호흡

처음에는 `CFG`에서 한 항목만 수정하고 페이지를 새로고침한다. 아래 수치는 이 코드와 버전에서 직접 실행한 결과다. 설정 하나가 모든 시드에서 같은 개수나 같은 느낌을 보장하는 것은 아니다.

| 바꾼 설정 | 실행 결과 | 화면에서 살펴볼 점 |
|---|---|---|
| 기본값 | 19개 영역 | 큰 면과 작은 면의 무게가 함께 느껴지는가 |
| `maxDepth: 4` | 11개 영역 | 세부를 덜어냈을 때 큰 면의 비율이 충분히 흥미로운가 |
| `stopChance: 0` | 63개 영역 | 깊이·크기 제한까지 나눠져 작은 면이 많아졌는가 |
| `gap: 16` | 같은 19개 영역, 같은 분할 좌표 | 색면 사이 배경이 넓어지며 연결감이 어떻게 달라지는가 |
| `seed: 32` | 29개 영역 | 같은 규칙 안에서 다른 구조를 골라낼 수 있는가 |

`maxDepth`는 세부를 얼마나 허용할지 정하는 상한이다. `stopChance`는 그 상한에 이르기 전에 큰 면을 남기는 장치다. 둘은 같은 역할이 아니다. 깊이를 낮추면 전체적으로 단순해지고, 중단 확률을 두면 일찍 멈춘 큰 면과 더 나뉜 작은 면이 섞인다. 다만 깊이나 크기 제한을 바꾸면 난수 소비 순서도 달라져, 이전 구성을 그대로 둔 채 일부만 추가되거나 제거되지는 않을 수 있다.

`gap`은 분할 구조와 독립적으로 비교하기 좋다. 좁은 틈은 면들을 하나의 큰 구조로 묶고, 넓은 틈은 각각을 분리된 조각처럼 읽히게 한다. `0 <= gap < minSide` 범위에서 시작한다. 더 큰 틈을 쓰고 싶다면 최소 크기도 함께 조정해야 한다. 음수 크기의 사각형이 생긴 뒤 화면만 보고 원인을 찾는 일을 피할 수 있다.

색을 바꿀 때는 먼저 `COLORS`의 값만 교체해 본다. 현재 코드는 각 색을 같은 확률로 고르지만, 면의 크기가 서로 다르므로 최종 화면에서 각 색이 차지하는 면적은 같지 않다. 넓은 색면이 우연히 강한 주황색을 받으면 작품의 중심도 그쪽으로 옮겨간다. 특정 색을 작은 영역에만 쓰거나, 가장 큰 영역에 차분한 색을 배정하는 방식은 다음 실험이 될 수 있다. 이 글의 최소 예제에는 그 선택 규칙까지 넣지 않았다.

## AI에 수정할 위치를 좁혀 주기

기본 결과를 본 뒤 AI에게는 한 가지 변경과 보존할 조건을 함께 요청한다. 예를 들어 “분할 함수는 그대로 두고, 가장 큰 면 하나만 짙은 색으로 그려줘”라고 하면 수정 범위가 색 배정 부분으로 좁혀진다. “같은 시드의 분할 좌표가 바뀌지 않는지도 확인해줘”를 덧붙이면, 그럴듯한 결과만 제시하고 계산 구조를 바꾼 답변을 발견하기 쉬워진다.

이 글에서는 기본 설정 반복 실행과 변수 변경을 브라우저에서 확인했다. 별도 기하 검사에서는 한 번 나눈 두 자식의 좌표, 작은 영역의 종료, 극단적인 분할 비율에서의 경계·면적·겹침, 중단 확률의 적용 시점을 확인했다. 그래도 전시 크기나 다른 화면 비율에서의 시각적 균형까지 자동으로 판정한 것은 아니다. 실제 출력 크기에서 큰 면이 너무 무겁지 않은지, 작은 면이 잡음처럼 보이지 않는지는 다시 골라야 한다.

브라우저 페이지에 포커스를 둔 뒤 `S`를 누르면 PNG를 저장한다. 실제로 `recursive-panels.png`가 내려받아지는 것까지 확인했다. 저장 대화상자나 다운로드 위치는 브라우저 설정에 따라 달라질 수 있다. [saveCanvas 문서](https://p5js.org/reference/p5/saveCanvas/)의 동작과 같다. `pixelDensity(1)`을 지정했으므로 이 예제의 PNG는 960×540이다. 더 크게 출력하려면 캔버스뿐 아니라 바깥 여백, 최소 크기, 틈의 비례도 함께 설계해야 한다.

재귀 분할로 만드는 작품에서 AI가 도울 수 있는 부분은 규칙을 구현하고, 바꾸려는 변수와 보존할 조건을 코드로 분리하는 일이다. 그 규칙으로 나온 여러 화면 가운데 무엇을 남길지는 제작자의 판단으로 남는다. 작은 면을 더 만들기 전에 큰 면 하나가 어디에 머물러야 하는지 보는 것만으로도 같은 알고리즘의 결과가 달라진다.
