# 나를 인터뷰하는 온톨로지

사용자가 자신의 이야기를 말하면, 그 안의 대상과 관계를 정리하고 실제 질문에 쓰게 한다. 사용자가 온톨로지 용어나 JSON 형식을 알아야 할 필요는 없다. 처음부터 긴 설문이나 전체 그래프를 요구하지 않는다.

## 시작과 재개

- 이미 받은 목표·이름·표기 선호·자료와 이전 인터뷰를 먼저 확인한다. 사용 가능한 자료가 있으면 읽고, 알고 있는 내용과 확인할 내용을 나눈다. 자료 접근 권한이 없으면 대화만으로 시작한다.
- 기존 `interview-state.json`이 있으면 직전 산출물과 미확인 사항을 읽고 이어간다. 이미 답한 질문을 반복하거나 사용자의 실제 이력을 가상 페르소나로 바꾸지 않는다.
- 첫 대화에서는 **이 온톨로지로 답하고 싶은 질문이나 도움받고 싶은 일**부터 정한다. 목표가 정해졌다면 바로 관련 경험을 묻는다. 한 번에 1~3개의 짧고 답하기 쉬운 질문만 한다.
- 출력 위치가 정해져 있으면 따른다. AKM을 사용하는 환경에서는 INDEX와 ROUTER의 저장 위치·분류·원문 보존 규칙을 우선한다. 별도 지식베이스 규칙이 없는 일반 작업 폴더에서는 `personal-ontology/`를 기본 제안으로 사용한다. 개인 경로나 특정 AKM 설치를 가정하지 않는다.

## 대화로 확장하기

필요할 때 [인터뷰 안내](references/interview-guide.md)를 참고한다. 답변을 바탕으로 다음 질문을 고르며, 정해진 설문을 순서대로 모두 묻지 않는다.

1. **작은 시작:** 본인, 지금 하는 일, 연결된 사람·자료 등 5~10개 대상부터 정리한다. 매 대화 후 “이렇게 이해했습니다”라는 짧은 관계 문장과 새로 확인할 부분을 보여준다. 사용자가 보충·정정하면 즉시 반영한다.
2. **범위 넓히기:** 직업·역할뿐 아니라 작품, 프로젝트, 구체적인 작업, 개념·관심사, 협업, 교육·학습, 과거 경력을 살핀다. 커리어 DB가 있다면 처음 발견한 몇 항목에만 고정하지 말고 활동 분야를 먼저 훑는다. 사용자의 질문에 필요한 영역을 우선 연결하고 나머지는 확장 후보로 남긴다.
3. **관계 뜻 묻기:** “함께했다”를 담당·검토·승인으로 바꾸지 않는다. 누가 어떤 활동에서 무슨 역할을 했는지 묻는다. 하나의 프로젝트와 그 안의 작품, 작품 제작 과정의 작업을 구별한다.
4. **한 번 활용하기:** 작은 구조로 첫 질문에 답한다. 따라간 관계와 근거, 답할 수 없는 부분을 함께 보여준다. 사용자가 “이건 달라요”라고 말하면 관계를 수정하고 같은 질문에 다시 답한다.
5. **다음 사용:** 답변을 보강할 자료·관계만 다음 질문으로 남긴다. 모르는 답은 미확인으로 두고 다른 부분을 계속 진행한다. 인터뷰를 모두 끝내야 저장·활용할 수 있는 구조로 만들지 않는다.

## 사실·범위·표기

- 사용자 진술과 제공 문서에 근거한 관계, 에이전트의 해석·가설, 미확인 사항을 구별한다. 진술은 “인터뷰 I001에서 본인이 설명함”처럼 출처를 남긴다. 본인 진술을 외부 증빙까지 검증한 사실로 포장하지 않는다.
- 직업·관심으로 능력이나 작업 책임을 추론하지 않는다. 구상 중인 작품, 진행 중인 프로젝트, 재학·수료, 입상·파이널리스트를 서로 바꾸지 않는다. 과거 경력의 역할은 그 활동 범위 안에서 읽는다.
- 이름·기관·닉네임의 공개 범위는 사용자의 지시를 따른다. 본인 실명 유지와 주변 인물 익명화를 함께 요청했다면 중심 인물은 유지하고 주변만 가린다. 같은 대상에는 같은 별칭을 사용하고 이름이 비슷하다는 이유만으로 합치지 않는다. 근거 문장·파일명·URL도 같은 범위로 처리한다.
- 참고 예제는 사용자의 이력이 아니다. 이 스킬에는 빈 사용자 모델을 사용한다. 별도로 제공된 육대근 사례를 새 사용자의 데이터로 복사하지 않는다.

## 파일로 남기고 확인하기

파일 작성 전에 [데이터 규약](references/data-contract.md)을 읽는다. 실행 도구가 있다면 포함된 `scripts/ontology.mjs`로 구조를 검사하고 Markdown을 만든다. Bun 또는 Node.js 중 있는 런타임을 사용한다.

```bash
node scripts/ontology.mjs init --dir personal-ontology --name "사용자가 정한 이름"
node scripts/ontology.mjs validate personal-ontology/ontology.json
node scripts/ontology.mjs export personal-ontology/ontology.json --out personal-ontology/ontology.md
```

스크립트 경로는 **이 스킬 폴더 기준**이다. 다른 작업 폴더에서 실행할 때는 스킬 폴더의 실제 절대경로를 사용한다. `init`은 기존 파일을 덮어쓰지 않는다. 이미 파일이 있으면 읽고 이어간다.

- `interview.md`: 질문·답변의 필요한 발췌, I001 같은 출처 ID, 정정 내역.
- `ontology.json` / `ontology.md`: 대상·관계·뜻·근거·확인 상태·활동 범위·시기. JSON은 웹 실습실에서 가져올 수 있다.
- `questions.md`: 활용 질문, 근거를 따라 작성한 실제 에이전트 답변, 미확인 사항, 관계 수정 전후.
- `interview-state.json`: 현재 목표·완료한 주제·미확인 사항·다음 질문·마지막 산출물 위치. 다음 대화에서 이어갈 만큼만 기록한다.

파일을 만들 수 없는 환경에서는 같은 내용을 코드블록과 문서로 전달하고, 파일 저장·스크립트 검증을 실행했다고 말하지 않는다. 구조 검사 통과와 사실 확인, 브라우저 규칙 조회와 실제 에이전트 답변을 구분한다. 기본 과정에 Neo4j·Jev·유료 API를 요구하지 않는다.
