# 내 방향으로 지식을 계속 확장하기

[4주차 웹 교안](https://dexa.art/ontology/study/week4.html#growth) · [실행 요청문](https://dexa.art/ontology/study/downloads/week4/prompts.md) · [범위 점검표](https://dexa.art/ontology/study/downloads/week4/coverage-map.md)

지속 확장은 이전 실행에서 검증한 지식과 남은 질문을 다음 실행의 출발점으로 삼는 일입니다. 같은 자료를 매번 요약하거나 노트 수를 채우는 것으로 완료를 판단하지 않습니다.

## 1. 확장의 방향 세 가지

| 방식 | 언제 쓰는가 | 한국사 지식공간의 질문 예 |
| --- | --- | --- |
| 깊게 파기 | 설명은 있지만 근거·조건·예외가 부족할 때 | 한 제도의 도입 이유와 시행 이후의 차이를 사료로 구별할 수 있는가? |
| 옆으로 넓히기 | 특정 시기·지역·주제에 자료가 몰렸을 때 | 같은 시기의 정치·경제·생활·문화 중 아직 답할 수 없는 영역은 무엇인가? |
| 분야 사이 연결하기 | 따로 알던 지식을 함께 써야 할 때 | 제도 변화와 지역 생활의 관련성을 어떤 근거로 설명할 수 있는가? |

세 방식 모두 기존 질문·주장·출처와 연결합니다. 새 분야의 목적이나 자료 기준이 다르면 그 분야만 짧게 인터뷰하고 기존 공간에 추가합니다. 전체 공간의 인터뷰와 초기 구축을 반복하지 않습니다.

## 2. 내가 원하는 방향으로 유도하기

에이전트가 고르는 다음 질문의 기준을 운영 규칙에 남깁니다. 말로만 정한 기준은 다음 세션에 빠질 수 있으므로 기존 정책 파일에 저장하고 다음 실행에서 다시 읽게 합니다.

1. **목적과 사용할 결과:** 무엇을 판단하거나 만들기 위해 배우는가? 예: 전시 수업에 쓸 조선 생활사 설명.
2. **집중 범위와 제외 범위:** 시대·지역·대상·주제를 구체화합니다. 예: 조선 전기 생활사, 현대 정치 평가는 이번 범위에서 제외.
3. **우선순위와 깊이:** 당장 막힌 질문 → 핵심 주제 → 인접 주제의 순서를 정합니다. ‘출처 한 곳의 개요’와 ‘상반된 해석을 비교하는 설명’을 구별합니다.
4. **자료 기준:** 허용한 폴더·웹 출처, 최신성, 원문 확인 수준을 정합니다. 직접 읽은 자료와 검색 결과 요약을 구분합니다.
5. **완료와 재검토:** 어떤 질문에 근거를 붙여 답해야 하는지, 몇 사이클 뒤 방향을 점검할지 정합니다.

‘생활사 60%, 제도 30%, 인접 분야 10%’ 같은 비율을 쓸 수도 있습니다. 이는 **사용자가 선택하는 탐색 예산의 예시**이며 정답률·성장률이나 스킬의 기본 자동 배분 기능이 아닙니다. 실제로 적용하려면 운영 규칙에 적고 실행 기록으로 확인합니다.

방향을 바꿀 때는 기존 대기 질문의 순서를 바꾸고 제외된 질문을 보류합니다. 기존 근거와 기록은 보존합니다. **관심 방향과 원하는 결론은 다릅니다.** 특정 결론에 맞춰 자료를 고르지 말고 반례·상반된 해석·다른 적용 조건도 함께 남깁니다.

## 3. 넓은 범위는 지도를 만들고 순환합니다

‘한국사를 전부 확장해줘’처럼 한 번에 맡기기보다 범위를 나눕니다.

1. **전체 지도:** 기존 색인에서 큰 영역 5–8개 정도를 초안으로 정합니다. 개수는 실습 예시이며 도메인에 따라 바꿉니다. 모든 원문을 한꺼번에 읽거나 재분류할 필요는 없습니다.
2. **대표 질문:** 영역마다 ‘이 정도는 설명하고 싶다’는 질문을 1–3개 둡니다. 파일이 있다는 이유만으로 답할 수 있다고 표시하지 않습니다.
3. **현재 상태:** 미탐색 / 조사 중 / 근거로 답변 가능 / 재검토로 표시합니다. 답변 가능에는 실제 답·출처·검토일을 연결합니다.
4. **얕게 한 바퀴:** 중요하지만 비어 있는 영역부터 한 사이클에 한 영역, 질문 하나를 처리합니다. 이미 자료가 많은 분야만 반복하지 않습니다.
5. **필요한 곳을 깊게:** 실제 질문에 자주 쓰이거나 설명이 충돌하는 영역을 다음 깊이 탐구 대상으로 정합니다.
6. **영역 사이 연결:** 두 영역을 잇는 관계의 뜻·방향·조건·근거를 확인한 뒤 연결합니다. 단어가 비슷하다는 이유만으로 인과관계를 만들지 않습니다.

범위 점검표의 예시는 조사 계획이며 한국사에 관한 검증된 결론이나 실제로 완료된 조사 결과가 아닙니다. [빈 양식과 예시](https://dexa.art/ontology/study/downloads/week4/coverage-map.md)를 자기 분야에 맞게 고칩니다.

## 4. 한 번의 실행을 다음 실행에 연결하기

`목적·정책 확인 → 범위 점검표와 대기 질문 확인 → 질문 하나 선택 → 근거 탐색 → 기존 지식 보강 → 관계 연결 → 검사와 재질의 → 다음 작업 저장`

- 같은 질문의 근거·조건이 좋아지면 기존 노트를 보강합니다.
- 다른 뜻의 개념은 별도 ID로 두고 관계를 설명합니다.
- 충분한 근거와 독립적인 질문이 있을 때 새 노트를 만듭니다.
- 새 근거가 없으면 ‘변경 없음’, 충돌이 해결되지 않으면 ‘재검토’로 남깁니다.
- 질문별로 선택 이유·출처·상태·시도한 리비전·다음 재개 위치를 기록합니다.
- 같은 상태에서 실패한 질문은 새 자료·조건 변화·사용자 지시가 생기기 전까지 반복하지 않습니다. 독립적인 다른 질문은 진행할 수 있습니다.

실습 기본 한도는 **질문 1개, 새 출처 최대 3개, 작업 최대 3개 또는 15분 중 먼저 도달한 한도**입니다. 검증 결과가 있어야 완료이고, 예산이 끝난 것은 완료가 아닙니다.

## 5. 큰 지식베이스의 시간과 토큰 관리

전체 문서를 매 사이클 프롬프트에 넣지 않습니다. 색인·질문·최근 상태에서 시작해 관련 개념과 관계를 찾고, 답을 검증할 원문 부분을 읽습니다. 변경된 주장과 연결된 설명부터 검사하되 운영 규칙에서 정한 주기에 전체 구조 점검도 수행합니다.

정형 자료의 필터·개수·집계는 가능한 경우 로컬 코드나 데이터베이스로 계산하고, 에이전트는 조건 해석·근거·예외를 검토합니다. 도구가 없다면 숫자를 추측하지 않습니다. 실제 사용량을 볼 수 있을 때만 기록하며 절감률을 미리 보장하지 않습니다.

예산은 출처 수·작업 수·시간뿐 아니라 호스트가 실제로 확인·제어할 수 있는 토큰 한도를 포함할 수 있습니다. 토큰 사용량을 알 수 없으면 ‘미측정’으로 남기고 시간·작업 한도를 사용합니다.

## 6. 계속 운영하는 세 가지 방식

| 방식 | 실행 조건 | 남길 것 |
| --- | --- | --- |
| 수동 재개 | 내가 필요할 때 같은 지식공간에서 재개 요청 | 이전 리비전·미완료 작업·다음 질문 |
| 한정된 연속 실행 | 현재 실행에서 최대 사이클 수와 전체 예산을 지정 | 각 사이클의 검증·소요 시간·전체 중단 이유 |
| 예약 실행 | 호스트 스케줄러에 주기·루트·정책·예산을 등록하고 실제 등록 상태 확인 | 예약 ID·다음 실행 시각·최근 실행 결과 |

연속 실행 예시: 최대 3사이클, 전체 45분·새 출처 9개·작업 9개 중 먼저 도달한 한도. 각 사이클은 앞의 기본 한도를 유지합니다. 현재 호스트에서 실행을 이어갈 수 없으면 체크포인트를 남기고 멈춥니다. **스킬 설치만으로 백그라운드 실행이나 예약이 시작되지는 않습니다.**

여러 작업이 같은 모델·색인을 동시에 덮어쓰지 않도록 한 지식공간의 반영은 한 작성자가 순서대로 수행합니다. 새 자료가 들어오거나 질문을 하다가 빈틈을 발견했을 때도 같은 운영 사이클로 돌아옵니다.

## 7. 확장이 잘되고 있는지 판단하기

같은 질문의 답·근거·미확인·시간을 전후 비교합니다. 넓게 확장했을 때는 영역별 대표 질문을 다시 확인합니다. 평가 결과에는 다음을 함께 남깁니다.

- 이제 근거를 붙여 답할 수 있는 질문과 여전히 답하지 못하는 질문
- 기존 설명에서 수정된 조건·예외·오류
- 빈 영역, 근거 충돌, 오래된 출처와 다음 조사 이유
- 실제 소요 시간과 확인 가능한 사용량
- 다음 3사이클에서 유지하거나 바꿀 우선순위

‘전체 지식 완성’ 대신 **선언한 범위의 질문을 현재 근거로 어디까지 다뤘는가**로 보고합니다. 지식의 복리는 이렇게 검증한 결과와 개선한 운영 기준을 다음 실행에서 재사용할 때 생깁니다.
