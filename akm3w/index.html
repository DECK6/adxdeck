매끄러운 초안을 곧바로 믿지 않습니다. 원본을 보존하고, 초안과 분리된 질문을 만들고, 더 강한 근거가 구체적인 충돌을 보여 줄 때만 최소한으로 고칩니다.

이번 주 성공 기준 — 한 번 검증하고, 맞던 것은 지키고, 근거가 부족하면 판정과 재개 조건을 남긴 채 멈춥니다.

  3. 질문을 초안과 분리

01 / FAILURE SCENE

문장은 완벽했지만, 문은 잠겨 있었습니다.

가상의 공지 한 장에서 시작합니다. 실패 원인은 문체가 아니라 사실을 확인하고 수정할 권한을 정하는 절차가 없었다는 데 있습니다.

FICTIONAL CASE / 봄빛도서관

민서는 AI가 정리한 공지를 믿고 화요일 저녁에 도착했습니다.

AI 초안은 화요일 · 정원 15명 · 개인 노트북 필수라고 썼습니다. 가상 원문은 수요일 18:00–20:00 · 정원 12명 · 장비는 별도 안내였습니다. 원래 맞았던 신청 마감 월요일 18:00도 함께 지켜야 합니다.

요일 오류원문과 직접 모순
수치 변형12명을 15명으로 변경
근거 없는 추가장비 의무를 새로 단정
“더 자연스럽게 다시 써 줘”는 세 오류를 고치지 못할 수 있습니다. 반대로 전부 새로 쓰면 맞던 마감 정보까지 사라질 수 있습니다. 그래서 초안 전체가 아니라 근거가 가리킨 최소 범위만 바꿉니다.
02 / REFINE ≠ VERIFY

다듬기는 후보를 만들고, 검증은 변경 권한을 심사합니다.

둘 다 유용하지만 질문이 다릅니다. 표현을 좋아지게 하는 일과 사실을 바꿔도 되는지 결정하는 일을 한 덩어리로 섞지 않습니다.

REFINEMENT

더 나은 표현 후보

  • 문체, 구조, 길이, 설명 순서를 개선합니다.
  • 같은 모델의 비평도 값싼 아이디어 신호로 쓸 수 있습니다.
  • 하지만 공유된 지식과 편향 때문에 같은 오류를 반복할 수 있습니다.
VERIFICATION

보존·수정·보류의 증거 절차

  • 검사 기준과 초안을 먼저 고정합니다.
  • 독립 질문을 원문·도구·결정적 검사에 연결합니다.
  • 근거가 없으면 바꾸지 않고 멈춥니다.

증거 독립성 사다리

위로 갈수록 모든 문제의 절대적 진실이 되는 것이 아니라, 초안과 공유하는 오류가 줄어드는 방향입니다.

같은 모델 비평

누락·표현 문제 후보. 사실 증명은 아님.

독립 샘플

우연성은 줄지만 공동 오류는 남음.

초안을 숨긴 질문

초안 문구의 고정 효과를 줄임.

다른 모델 판정

자기확증은 줄지만 판정 잡음이 남음.

외부 자료 회수

원문 후보를 찾음. 검색 순위는 권위가 아님.

원문·도구 직접 확인

주장과 외부 현실을 직접 대조.

결정적 검사

고정 기준으로 파일·수치·구문·테스트 확인.

책임 있는 승인

고영향 가치 판단과 책임의 최종 경계.

03 / 2 LENSES + 10 METHODS

AKM 운영 렌즈 2개 + 논문 방법 10개

비교 행은 12개지만 “논문 12편”이 아닙니다. DEER와 KSI는 AKM에서 판단을 조직하는 렌즈이고, 나머지 열 편은 refinement·verification·correction과 판정 한계를 살피는 별도 방법 묶음입니다.

2 + 10 ≠ 12 papersDEER는 한 산출물의 평가 깊이를 고르는 렌즈, KSI는 여러 작업의 경험을 조건부 지식 후보로 다루는 렌즈입니다.
구분·항목핵심 작동feedback·evidence잘 쓰이는 자리중단·경계
AKM LENS 1/2
DEER		과업별 품질 차원과 위험 Tier로 평가 깊이를 조절요청·수용 기준, 직접 원문, claim 위치, 파일 재확인공개 글·보고서·제안서의 다차원 평가평가표를 진실 판정기로 쓰지 않음. 중요한 주장이 미해결이면 HOLD.
AKM LENS 2/2
KSI		여러 작업의 경험을 지지·반박·종합해 조건부 후보로 남김실제 실행 결과, 외부 근거, 분리된 전이 비교반복 실패에서 재사용 가능한 Learn Back 후보 만들기한 번의 합의나 성공을 전역 규칙으로 승격하지 않음.

04 / ONE BOUNDED CYCLE

한 번의 보수적 correction cycle

검증은 “다른 답 하나 더”가 아니라 초안의 어떤 부분을 유지·수정·보류할지 정하는 유한한 절차입니다.

Baseline 동결

초안, 목적, 필수 항목, 금지 항목을 변경 없이 보존합니다.

범위 선택

결과 판정을 바꿀 고영향 항목 3–5개만 고릅니다.

독립 질문

초안 결론을 반복하지 않는 짧고 반증 가능한 질문을 만듭니다.

직접 evidence

질문을 원문·도구·고정된 검사 기준에 대고 답합니다.

최소 correction

구체적 충돌이나 필수 기준 실패가 입증된 부분만 고칩니다.

No-degradation

맞던 주장, 필수 내용, 형식과 안전 경계가 나빠지지 않았는지 다시 읽습니다.

Verdict

PASS, PASS_WITH_NOTE, HOLD, FAIL 중 하나를 선택합니다.

STOP / Learn Back

상한에서 멈추고, 조건이 완전한 규칙만 후보로 남깁니다.

WORKED EXAMPLE / 봄빛도서관

근거가 가리킨 세 곳만 바꾸기

BASELINE
“글쓰기실은 화요일 18:00–20:00에 열립니다. 정원은 15명입니다. 월요일 18:00까지 신청하세요. 개인 노트북이 필수입니다.”

독립 질문가상 원문의 답Baseline과 관계조치
요일·시간은?수요일 18:00–20:00요일이 구체적으로 충돌수요일로 최소 수정
정원은?12명15명과 구체적으로 충돌12명으로 최소 수정
신청 마감은?월요일 18:00일치그대로 보존
노트북이 필수인가?장비는 별도 안내필수 단정은 지원되지 않음별도 안내로 범위를 낮춤

FINAL AFTER ONE CYCLE
“봄빛도서관 청소년 글쓰기실은 수요일 18:00–20:00에 열립니다. 정원은 12명입니다. 월요일 18:00까지 신청하세요. 장비 안내는 별도로 제공됩니다.”

No-degradation: 네 문장과 월요일 마감이 보존되었고 새 장소·비용·성과 주장은 생기지 않았습니다. Verdict: PASS · cycle 1/1 · STOP.

PASS

적용한 검사와 필수 기준 통과. 증거와 최종본을 보존하고 종료.

PASS_WITH_NOTE

사용 가능하지만 낮은 위험의 범위·불확실성을 주석과 함께 유지.

HOLD

중요 근거·권한·범위가 부족. 다음 한 가지 확인과 재개 조건을 적고 중단.

FAIL

오해 위험이 크거나 필수 요구가 빠져 작은 수정으로 회복하기 어려움.

05 / OVER-VERIFICATION

검증을 늘릴수록 새 실패가 쌓일 수 있습니다.

추가 반복은 관찰만 늘리지 않습니다. 새 질문, 판정, 수정문이 다음 입력이 되며 잘못된 비평 하나가 결과와 학습 규칙까지 바꿀 수 있습니다.

False correction

맞던 baseline을 약한 반대 의견 때문에 틀리게 바꿉니다.

SIGNAL → 수정 후 검사 결과가 악화

Critique noise

매회 새로운 흠이 생겨 수용 기준 밖의 끝없는 할 일이 됩니다.

RESPONSE → 질문 3–5개 동결

새 모순 생성

한 문장을 고치며 다른 문장·표·요약과 새로 충돌합니다.

RESPONSE → 재확인 뒤 중대 모순이면 HOLD

비용 inflation

표본·검색·판정·재작성이 본 작업의 위험과 가치보다 커집니다.

RESPONSE → Tier·범위·상한 재조정

Generic HOLD

결손과 책임 경계가 없는 보류가 쌓여 아무도 재개하지 못합니다.

RESPONSE → 결손 1개 + 다음 확인 1개

Wrong Learn Back

우연한 실패나 불안정한 판정을 전역 절차로 학습합니다.

RESPONSE → 적용·비적용·반증 조건 필수
06 / TIER · STOP · HANDOFF

검증 깊이와 멈출 지점을 먼저 고릅니다.

중요도가 다른 작업을 같은 강도로 검증하지 않습니다. 위험, 재사용성, 실패 이력을 보고 Tier를 고른 뒤 correction 상한과 이관 조건을 고정합니다.

Tier언제필요한 검증Correction cap막히면
Tier 0 Quick저장하지 않는 낮은 위험 답필요한 정확 조회·도구 확인만0회범위 축소 또는 불확실성 표시
Tier 1 Durable Note다시 쓸 일반 노트·요약원문 직접 확인, 저장 결과 재확인최대 1회근거 없는 재작성 거부, 해당 주장만 HOLD
Tier 2 Deep Report공개 글·강의·제안서·중요 합성고영향 질문 3–5개, 직접 근거, 결정적 검사최대 1회미해결 주장을 낮추거나 HOLD하고 종료
Tier 3 High-stakes안전·의료·법률·계약·공식 제출주장별 근거표, 권위 확인, 책임 있는 사람의 승인최대 2회권한 있는 근거 없이는 공개 금지·HOLD
Repeated failure같은 실패 형태가 재발이전 baseline과 실패 조건을 동결하고 Tier 상향최대 2회같은 실패가 또 나오면 실행 중단 후 절차 후보만 남김
QUESTION 01

틀리면 누구에게 어떤 영향이 있나?

영향이 크면 Tier를 높이고 사람의 책임 경계를 남깁니다.

QUESTION 02

어떤 근거가 실제로 결정권을 가지나?

검색 요약보다 최신 원문, 실제 도구 결과, 고정 검사를 우선합니다.

QUESTION 03

언제 자동 반복을 끝낼 것인가?

상한, 비열화, 판정 불일치, 근거 부재를 종료 조건으로 고정합니다.

즉시 멈추는 조건

  1. correction 상한에 도달했습니다.
  2. 필요한 직접·결정적·권한 있는 근거가 없습니다.
  3. 수정본이 맞던 주장·필수 내용·안전 경계를 악화시켰습니다.
  4. 판정 불일치를 더 강한 근거로 풀 수 없습니다.
  5. 재확인 뒤 새로운 중대 모순이 생겼습니다.
  6. 검증 비용이 위험과 재사용 가치보다 커졌습니다.

과제 2 — 파일 에이전트에 검증 경계 심기

언제 검증을 시작하고, 누가 정본을 쓰며, 어떤 실제 readback으로 수정하고, 언제 HOLD로 멈출지 운영 지침에 명시합니다.

개인정보 안전 가상 시나리오

  • 입력: sources/schedule.txt, sources/requirements.txt
  • 정본 목표: deliverables/event-brief.md
  • 필수: 제목, 일정, 정원, 신청 마감, 준비물, source 범위 주석
  • 금지: source에 없는 비용·승인·성과·연락처 추론, 허용되지 않은 파일 수정, 외부 공개
  • Tier: 공개용 교육 예시이므로 Tier 2
COPYABLE TEMPLATE / AGENT POLICY복사 대기
[AGENT INSTRUCTION START — BOUNDED FILE SELF-VERIFICATION]

ROLE AND AUTHORITY
- 너는 이 작업의 유일한 정본 작성자다.
- 검토자, 판정자, 표본 생성자는 조언할 수 있지만 정본 목표를 직접 쓰지 않는다.
- 허용된 target과 evidence file 외에는 만들거나 수정하지 않는다.
- 외부 공개, 전송, 배포, 계정 접근은 별도 사람 승인 없이는 금지한다.

TASK VARIABLES
- task goal: [산출물과 사용 장면]
- audience: [독자]
- canonical target: [workspace-relative path]
- allowed source files: [workspace-relative path 목록]
- required output files: [정본과 evidence file 목록]
- forbidden scope: [수정 금지 파일, 외부 공개, 민감정보]
- acceptance checks: [필수 heading, 수치, parser, test, lint, path safety]
- risk tier: [Tier 0 / Tier 1 / Tier 2 / Tier 3 / repeated failure]

PRIVACY AND CLAIM BOUNDARY
- 실제 개인정보, 비공개 대화, 계정 정보, 인증값, 내부 기록을 공개 산출물에 쓰지 않는다.
- 읽지 않은 파일, 실행하지 않은 도구, 발생하지 않은 효과를 완료 증거로 주장하지 않는다.
- source가 말하지 않은 성과·승인·비용·정책을 추론하지 않는다.
- 완료 보고에는 workspace-relative path만 쓴다.

TRIGGER AND TIER RULES
- Tier 0: 저장하지 않는 낮은 위험 답. formal correction loop 0회, 필요한 exact check만 한다.
- Tier 1: 재사용 파일. source direct-read, target readback, format check, correction 최대 1회.
- Tier 2: 공개 글·강의·제안서·중요 합성. 고영향 질문 3–5개, 직접·도구·결정적 evidence, correction 최대 1회, readback 1회.
- Tier 3: 안전·의료·법률·계약·공식 제출. 주장별 근거표와 책임 있는 사람의 승인을 요구하고 correction 최대 2회.
- repeated failure: 이전 실패 형태와 baseline을 동결하고 Tier 2 또는 3으로 올리되 correction 최대 2회.

PHASE 0 — PREREQUISITES AND SCOPE
1. allowed source files와 canonical target을 직접 확인한다.
2. source가 없거나 읽을 수 없으면 추측하지 않고 HOLD한다.
3. required output files와 forbidden scope를 다시 적어 범위를 고정한다.
4. 정본 작성자가 한 명인지 확인한다. 둘 이상이면 쓰지 않고 HOLD한다.

PHASE 1 — CREATE AND FREEZE BASELINE
1. source를 직접 읽고 첫 완성 초안을 canonical target에 쓴다.
2. 초안을 즉시 다시 읽어 baseline artifact로 byte-for-byte 복사한다.
3. baseline artifact의 SHA-256을 실제 deterministic hash tool로 계산해 별도 파일에 기록한다.
4. hash tool을 실행할 수 없으면 계산했다고 주장하지 말고 HOLD한다.
5. baseline artifact와 baseline hash는 correction 과정에서 덮어쓰지 않는다.

PHASE 2 — PLAN INDEPENDENT QUESTIONS
1. risk tier가 요구하는 수만큼 verdict-changing question만 만든다.
2. 날짜, 수치, 주체, 필수 요구, 금지 범위, 실행 결과를 원자적으로 묻는다.
3. 가능하면 verifier에게 baseline 문구를 보여 주지 않고 allowed source와 acceptance criteria만 제공한다.
4. verifier와 초안 분리 정도를 verification report에 기록한다.

PHASE 3 — EVIDENCE PRIORITY
1. authoritative source direct-read와 정확한 위치
2. 실제 tool/environment output
3. 동결된 acceptance criteria에 대한 deterministic check
4. 고영향 승인을 책임지는 사람 또는 도메인 권한자
5. 다른 모델의 disagreement signal
6. 같은 모델 표본의 consistency signal
7. 같은 모델의 intrinsic critique
낮은 단계만으로 높은 영향의 사실 수정을 승인하지 않는다.

PHASE 4 — CORRECTION GATE
1. evidence가 baseline과 구체적으로 충돌하거나 acceptance check 실패를 직접 입증할 때만 수정한다.
2. 수정 범위는 evidence가 지목한 최소 diff로 제한한다.
3. 각 변경에 baseline fragment, evidence 위치 또는 실제 tool result, correction reason을 남긴다.
4. 더 좋은 문체 제안, 단순 다수결, 모델 판정 점수만으로는 수정하지 않는다.
5. 허용된 cycle cap을 초과하지 않는다.

PHASE 5 — DIRECT READBACK AND NO-DEGRADATION
1. 수정한 canonical target을 도구로 다시 읽는다.
2. 존재, 비어 있지 않은 크기, 필수 섹션, source 범위 안의 주장, path safety, 구문, fence 균형, 요청된 deterministic tests를 확인한다.
3. final target을 baseline과 비교해 요청 적합성, 맞던 주장, 필수 내용, 형식, 안전 경계의 비열화를 확인한다.
4. baseline에서 통과한 항목이 final에서 실패하면 baseline을 복원하고 HOLD한다.
5. final SHA-256을 실제 hash tool로 계산해 별도 파일에 기록한다.

PHASE 6 — VERDICT AND STOP
- PASS: 적용한 검사를 통과했고 중요한 미해결이 없다.
- PASS_WITH_NOTE: 사용 가능하지만 낮은 위험의 caveat가 남는다.
- HOLD: 중요한 source, authority, scope, contradiction, regression 문제가 남는다.
- FAIL: 결과가 오해를 만들거나 필수 요구가 크게 빠져 제한 수정으로 회복하기 어렵다.
다음 중 하나면 즉시 stop하고 추가 self-critique를 금지한다.
- correction cap 도달
- 필요한 직접·결정적·권한 있는 evidence 부재
- no-degradation 실패
- 판정 불일치를 더 강한 evidence로 풀 수 없음
- readback 뒤 새로운 중대 contradiction 발생
HOLD에는 missing evidence, next single check, responsible authority, resume condition을 기록한다.

PHASE 7 — CONDITIONAL LEARN BACK
- 반복 가능한 실패 또는 성공 규칙이 있고 다음 필드를 모두 채울 수 있을 때만 candidate를 만든다.
- candidate rule, appliesWhen, doesNotApplyWhen, evidenceRefs, baseline hash, correction justification, regression evidence, uncertainty, falsifier, held-out transfer needed.
- 한 작업의 결과나 모델 판정만으로 정본 절차에 승격하지 않는다.
- 조건이 부족하면 Learn Back은 NONE이고 candidate file을 만들지 않는다.

학습자가 기억할 네 가지

  • DEER·KSI는 열 편의 논문 방법과 다른 층위의 AKM 적용 렌즈입니다.
  • 각 논문의 결과는 해당 과제·모델·버전·평가 설정에서 보고된 범위입니다.
  • SkillAxe, DISC, RuVerBench는 2026년 사전 공개 논문으로 읽습니다.
  • 같은 모델 비평, 표본 동의, 다른 모델 판정만으로 사실이나 공개 승인을 확정하지 않습니다.

직접 근거도 확인할 것

  • 원문이 해당 결정을 내릴 권위를 가지는지 봅니다.
  • 적용 범위와 기준 시점이 현재 작업에 맞는지 봅니다.
  • 결정적 검사는 작성된 규칙만 확인하며 가치 판단 전체를 보장하지 않습니다.
  • 한 번의 가상 실습은 AKM 전체의 효과나 일반적 인과를 입증하지 않습니다.
